# apps/desktop/src-tauri

The Tauri Rust process: the local `rusqlite` database, the filesystem blob cache, and the
`selftest` harness. The UI is the shared bundle in `apps/web/dist`
(`frontendDist: ../../web/dist`); nothing here renders.

| Path | What it is |
|---|---|
| `src/lib.rs` | App setup: opens the data directory, creates the window, registers the commands |
| `src/commands.rs` | `db_query`, `db_run`, `db_transaction`, `blob_put`, `blob_get`, `blob_has`, `blob_delete` — the contract with `packages/platform/src/tauri/adapters.ts` |
| `src/db.rs` | Statement-level SQL, free of Tauri types so it is unit tested directly |
| `src/migrations.rs` | The shared migrations in `packages/schemas/sqlite/migrations`, applied with the same bookkeeping as the browser runner |
| `src/blobs.rs` | Content-addressed files under `<data dir>/blobs` |
| `src/selftest.rs` | The end-to-end harness (`--features selftest`) |
| `capabilities/*.json` | What each window label may do (01 §10) |

Permissions are allow-listed per command: `build.rs` declares every command through
`AppManifest::commands`, which puts the app's commands into the ACL, so each one needs an explicit
`allow-…` grant in a capability. `capabilities/default.json` grants the seven storage commands to
the `main` window and nothing else — no plugin permissions, no filesystem scope. The
`selftest` capability adds `allow-selftest-report` for the harness window only; that window label
exists only when the app is launched with `BRAGI_SELFTEST_PHASE`, so the grant is inert in a normal
build.

`tauri.conf.json` defines **no** windows (`"windows": []`): `src/lib.rs` creates the one window, so
the harness can use a label of its own.

`gen/` and `permissions/autogenerated/` are regenerated by `tauri-build` on every build and are
gitignored. `icons/` holds the desktop sets; it is drawn by `scripts/make-icon.mjs` and expanded by
`npx tauri icon src-tauri/icons/source.png`. The Android/iOS sets that command also emits are left
out until a mobile target exists (01 §9).

**Status:** the platform shell (WP-0.5). The native engine host, deep links, OS media keys and the
updater arrive with later work packages.

[05 §7](../../../specs/05-backend-and-jobs.md) (the local schema).
