# WP-0.3 — `bragi-model` core + WASM

- **Spec refs:** [02](../../specs/02-song-model.md) (all), [01 §7](../../specs/01-architecture.md)
  (contracts), [13](../../specs/13-agent-guide.md) (rules + Definition of Done)
- **Depends on:** 0.2 (Done)
- **Size:** L
- **Branch:** `wp/0.3-bragi-model-core-wasm`

## Goal

Build the model logic on top of the Rust types WP-0.2 generated into
[`crates/bragi-model/src/generated/mod.rs`](../../crates/bragi-model/src/generated/mod.rs):
time mapping, `validate`, `apply` for every v1 op except `analysis.apply` and `region.adopt`,
`section_spans`, `resolve_region`, `canonical_json`, the commit hash, and `diff → EngineDelta`.
Expose it to TypeScript through the handle-based `wasm-bindgen` package in
[`packages/model-wasm`](../../packages/model-wasm).

**Acceptance (from [12](../../specs/12-roadmap.md)):**

1. 100% of ops have tests.
2. Fuzzing runs 10 000 iterations with no panics (proptest; random *valid* batches never produce
   invalid documents).
3. WASM bundle < 1.5 MB gzipped.
4. `apply` of a 50-op batch on a 10-minute document < 5 ms in WASM.

## Approach

### The crate is still `bragi-model`; the WASM glue is a sibling crate

`crates/bragi-model` stays a pure, `#![forbid(unsafe_code)]`, dependency-light library. The
`wasm-bindgen` bindings go in a new `crates/bragi-model-wasm` (crate-type `cdylib` + `rlib`), the
same shape as the existing `bragi-engine-wasm`. `wasm-bindgen --target web` writes the generated
package (JS glue, `.d.ts` and `.wasm`) into `packages/model-wasm`, which is **generated output**
(never hand-edited, [13 §1](../../specs/13-agent-guide.md)). This is a deviation from 01 §4, which
lists only `bragi-engine-wasm`; 01 §4 is updated to name `bragi-model-wasm`.

### Modules in `crates/bragi-model`

| Module | Contents |
|---|---|
| `time.rs` | `ticks_to_seconds`, `seconds_to_ticks`, `bar_beat_to_ticks`, `ticks_to_bar_beat`, and the tempo-map integral (step and linear segments) |
| `assets.rs` | `AssetIndex` — `AssetHash → AssetMeta`, the metadata `validate` needs to check clip ranges |
| `clipmath.rs` | `clip_end_tick`, `src_sample_at_tick`, `tick_at_src_sample` (per [`Warp`](../../packages/schemas/song/clip.schema.json) mode), `beat_ticks`, `bar_ticks` |
| `spans.rs` | `SectionSpan`, `section_spans` |
| `region.rs` | `ResolvedRegion`, `RegionSlice`, `resolve_region` |
| `canonical.rs` | `canonical_json`, `commit_id` (`cmt_` + 26 chars of base32 SHA-256), base32 |
| `diff.rs` | `EngineDelta`, `diff` |
| `validate.rs` | `ValidationError`, `ValidationCode`, `validate` (02 §4.3) |
| `apply/` | `apply`, one file per op family (project, tracks, fx, sections, clips, automation, tempo, key, region) |
| `error.rs` | `ApplyError`, `ValidationError` re-exports |
| `fx_catalog.rs` | Parses the shared `crates/bragi-dsp/fx_catalog.json` for invariant 5 |

Public API mirrors [02 §8](../../specs/02-song-model.md). `migrate` and `summarize_for_llm` are out
of scope (they belong to the analysis/planner WPs and have no input data yet) — see Deferrals.

### Handle-based WASM API (02 §8)

`crates/bragi-model-wasm` keeps a `thread_local` slab of loaded documents; callers pass an integer
handle:

```
loadProject(json) -> handle          freeDoc(handle)
assetIndexAdd(handle, assetsJson)    validateDoc(handle) -> errorsJson
applyBatch(handle, batchJson) -> newDocJson + commitId    (mutates the stored doc)
sectionSpans(handle) -> json         ticksToSeconds(handle, ticks) -> f64
secondsToTicks(handle, secs) -> i64  resolveRegion(handle, regionJson) -> json
diffDocs(prevHandle, nextHandle) -> json   canonicalJson(handle) -> string
commitId(parentsJson, batchJson, snapshotHash) -> string
```

Hot paths (`sectionSpans`, `ticksToSeconds`) read the handle and never re-serialise the document.

### Build & test wiring

- `scripts/build-model-wasm.mjs`: `cargo build -p bragi-model-wasm --target wasm32-unknown-unknown
  --release`, then `wasm-bindgen --target web --out-dir packages/model-wasm`, then writes
  `packages/model-wasm/package.json` and prints the gzipped size. Prerequisite: `wasm-bindgen-cli`
  at the version pinned in `Cargo.toml` (0.2.129).
- `pnpm build:model-wasm` runs it; `pnpm verify` runs it after `pnpm build:wasm`.
- `build:wasm` and `.github/workflows/ci.yml` gain `-p bragi-model-wasm`.

## Test plan (and where each proof lives)

| Criterion | Proof |
|---|---|
| Time mapping | `crates/bragi-model/tests/time.rs` — step vs linear tempo, round trips, bar/beat, negative ticks |
| `validate` covers 02 §4.3 | `crates/bragi-model/tests/validate.rs` — one case per invariant 1–7 |
| 100% of ops tested | `crates/bragi-model/tests/ops.rs` — a dedicated test per op (27 of 29; the other two are out of scope), plus `apply_matches_expected_doc` snapshots (`insta`) |
| Fuzzing 10 000 iterations | `crates/bragi-model/tests/fuzz.rs` — proptest generates random valid documents and batches; asserts `apply` never panics and the result re-validates. `BRAGI_FUZZ_CASES` overrides the count; the recorded run uses 10 000 |
| No panic on validated input | `#![deny(clippy::unwrap_used, clippy::expect_used)]` outside tests + the fuzz test |
| `canonical_json` stability | `tests/canonical.rs` — HashMap key order does not change the bytes; two serialisations are byte-identical; `commit_id` matches a fixed vector |
| `diff` → `EngineDelta` | `tests/diff.rs` — empty diff, per-op diffs, and a round trip through `apply` |
| `section_spans` / `resolve_region` | `tests/spans.rs`, `tests/region.rs` |
| WASM size < 1.5 MB gz | `scripts/build-model-wasm.mjs` prints it; recorded in the plan and the 12 §8 row |
| 50-op batch < 5 ms in WASM | `scripts/__tests__/model-wasm.test.mjs` (Vitest, Node) builds a 10-minute document, times a 50-op batch through the built package |
| Handle API works | the same Vitest file exercises every exported binding |

## Spec gaps found (resolved here unless noted)

| Gap | Resolution |
|---|---|
| 02 §2.2 does not say which side of a tempo point `curve` describes | Documented in `time.rs` and 02 §2.2: `curve` is the ramp **from this point to the next**; the tempo is the point's `bpm` at its tick |
| 02 §2.2 promises `bar_beat_to_ticks` / `ticks_to_bar_beat` but no signature | Added to 02 §8 with `(bar, beat)` where `beat` is 0-based within the bar |
| 02 §4.3.3 "covered by matching fades" is prose | Pinned in 02 §4.3: an overlap `[b.start, min(a.end,b.end))` needs `a.fadeOut ≥ a.end − b.start` and `b.fadeIn ≥ min(a.end,b.end) − b.start` |
| Q14 (derived clip/fx IDs on `section.duplicate`/`section.split`) | Resolved: derived IDs are `clp_`/`fx_` + the first 26 chars of base32 SHA-256 of `"derive:" + newSectionId + ":" + originalId`; documented in 02 §4.2 and 15 |
| Q15 (canonical JSON number formatting) | Resolved: `canonical_json` sorts keys (serde_json's default map) and writes an integral `f64` without a fractional part (`0`, `118`), otherwise the shortest round-tripping form; documented in 02 §2.1 and 15 |
| 04 §6.2 / 03 §6 name `crates/bragi-dsp/fx_catalog.json` but it does not exist | Created with the ranges in 03 §6; `bragi-model` `include_str!`s it for invariant 5 (cross-area touch, noted in the report) |
| `EngineDelta` is named in 02 §8 but never defined | Defined in `diff.rs` and written into 02 §8 |
| `key.transpose` "sets `pitchSemitones`" is ambiguous for an already-pitched clip | Treated as **additive** (a transpose) and documented in 02 §4.2 |
| `region.clear`'s "short fades" have no length | Fixed at 10 ms, equal-power, matching 02 §5.4's `region.adopt` boundary fades |

## Deferrals

- `migrate` (02 §8) — no v0 documents exist, so there is nothing to migrate; the first schema
  version bump creates the case.
- `summarize_for_llm` (02 §8) — needs the analysis bundle and the planner's context budget
  (WP-1.8 / WP-2.x).
- `analysis.apply` and `region.adopt` — explicitly out of scope for WP-0.3.
