# WP-1.3 — Worker: separation (+ bake-off → ADR-0004 part 1)

- **Spec refs:** [04 §4, §8, §9](../../specs/04-analysis-pipeline.md),
  [02 §3.4, §6](../../specs/02-song-model.md), [05 §4](../../specs/05-backend-and-jobs.md),
  [13](../../specs/13-agent-guide.md)
- **Depends on:** 0.7 (Done)
- **Size:** L
- **Branch:** `wp/1.3-worker-separation`

## Goal

A `separation` worker capability that turns the 48 kHz / 24-bit FLAC working asset into one FLAC
per stem plus a residual, with the model choice recorded in an ADR and the licences recorded in
`services/workers/MODELS.md`.

**Acceptance (from [12](../../specs/12-roadmap.md)):**
1. Σ stems + residual nulls against the working mix at ≤ −60 dBFS.
2. A 4-minute song separates in < 40 s on the reference GPU.
3. Licences are recorded.

## Environment constraints (stated up front)

- The machine is macOS 15 / arm64 (Apple M2 Pro, 32 GB). **There is no CUDA GPU**, so criterion 2
  cannot be measured. CPU and MPS timings are measured and recorded as such.
- **No eval set exists yet** (`fixtures/eval/` is empty; WP-1.2 owns the manifest and harness). The
  bake-off is therefore limited to speed, memory and plumbing checks on generated signals. **No
  separation-quality (SDR) number is claimed**; the ADR stays *Proposed* until the owner's eval
  set runs the real bake-off.
- No copyrighted audio is used or committed.

## Approach

### Contracts (already there)

`packages/schemas/analysis/separation.schema.json` (`SeparationResult`: `model`, `stems[]
{role, asset, rmsDb?}`, `residual`) and the `separation` effect of `analysis.apply` were defined
in WP-0.2/1.8. No schema change is needed. The job envelope is `JobInputs.assets.mix = <working
asset hash>`; outputs are `assets: { stem_<role>, residual }` and `blobs: { separation }`.

### Module layout (`services/workers/analysis`)

| File | Role |
|---|---|
| `capabilities/separation.py` | `CAPABILITY = "analysis.separation"`, `ParamsModel`, `run(job, ctx)`: decode, separate, encode, upload, build `SeparationResult` |
| `separation/pipeline.py` | Pure numpy: resample, chunk plan, linear crossfade stitch, clip + 24-bit quantise, residual, silent-stem drop. **No torch import**, so it is tested with a stub backend in CI |
| `separation/audio.py` | FLAC decode/encode (`soundfile`), 24-bit |
| `separation/demucs_backend.py` | The only module that imports `torch` / `demucs`; loads weights from a local, hash-verified directory; device selection (`cuda` > `mps` > `cpu`) |
| `models_lock.json` + `scripts/fetch_models.py` | Machine-readable pins (HF revision + SHA-256) the Docker build uses; a test keeps `MODELS.md` and the lock file in sync |

### Algorithm

1. Decode the working asset (float64, 48 kHz, 2 ch). Resample **once** to the model rate (44.1 kHz
   for HTDemucs) with a polyphase filter (`scipy.signal.resample_poly`, 147/160), rather than per
   chunk, so chunk joins don't also carry resampler edge effects.
2. Plan chunks: segment length `min(10 s, model.max_segment)`, 1 s overlap, final chunk anchored
   to the end. Stitch with a **linear crossfade across the overlap** (weights sum to 1 everywhere).
3. Resample each stem back to 48 kHz, trim/pad to the exact source length.
4. Clip stems to the FLAC range and quantise to 24 bit *before* computing the residual.
5. `residual = mix − Σ kept stems`, computed on the quantised stems, so it is the exact
   complement of what is stored. Dropped (silent) stems are *not* subtracted, so their sub
   −60 dBFS content ends up in the residual and the null still holds.
6. Drop stems whose whole-song RMS is < −60 dBFS.
7. Encode each FLAC, upload through `ctx.upload`, return `SeparationResult`.

Progress is reported per chunk and cancellation is checked between chunks. Inference runs in
`asyncio.to_thread` so the event loop keeps feeding progress and heartbeats.

### Weights

Pinned in `models_lock.json` (HuggingFace repo, commit, per-file SHA-256), listed in
`MODELS.md`. The Dockerfile downloads and verifies them at **image build** into
`/opt/bragi/models`; the worker loads from that directory and sets `HF_HUB_OFFLINE=1`. Weights
are never committed and never fetched at runtime.

### Dependencies

`torch`, `demucs` (MIT, 4.1.0, weights from the HuggingFace hub as safetensors), `soundfile`,
`scipy`, `numpy`. They go into a `models` **dependency group** of `bragi-analysis`, not the
default sync, so `pnpm verify` stays fast; the Docker image syncs it. ADR-0004 covers the new
major dependency (torch).

## Test plan

| Test | Needs weights | What it proves |
|---|---|---|
| chunk plan | no | coverage, overlap, last-chunk anchoring, short inputs |
| crossfade identity | no | identity backend → output equals input for any length (weights sum to 1) |
| residual null | no | stub backend + 24-bit FLAC round trip: `mix − Σ stems − residual` ≤ −60 dBFS (expected ≈ −130) |
| 44.1 kHz round trip | no | resample-in/resample-out + residual still nulls (by construction) |
| silent stem drop | no | stem at −70 dBFS is dropped and the null still holds |
| clipping | no | overshooting stems are clipped before the residual |
| capability `run` | no | stub backend, fake ctx: outputs, schema-valid `SeparationResult`, progress, cancel |
| lock ↔ MODELS.md | no | every pinned SHA-256 appears in `MODELS.md` |
| real HTDemucs 6s | **yes** (`BRAGI_WEIGHTS_DIR`, marker `weights`) | loads, separates 12 s synthetic, 6 stems, null ≤ −60 dBFS |

## Bake-off (what is and is not possible here)

Candidates: `htdemucs_6s` (v1 default), `htdemucs` (4-source), `htdemucs_ft` if the weights are
reachable, and a (Mel-band) RoFormer vocal model if feasible on CPU. Measured on a generated
4-minute stereo signal: wall time on CPU and MPS, peak memory, and parameter/file size. Quality
is **not** measured; the ADR says so and lists the eval-set procedure.

## Spec gaps found

- HTDemucs cannot run 10 s segments (its transformer is trained at 7.8 s and rejects longer
  ones), so 04 §4's "10 s segments" is an upper bound: the chunk length is clamped to the model's
  `max_allowed_segment`. Spec to be amended (04 §4), recorded under Deviations.
- 04 §4's "residual = mix − Σ stems" is ambiguous once silent stems are dropped; the definition
  above (subtract only the kept stems) is the one that keeps playback reconstruction exact.
- 05 §4.1 names the capability `analysis.separation`; the DAG stage is `separation`. The worker
  subscribes to `jobs.analysis.separation.*` as 05 says.
