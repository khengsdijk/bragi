# WP-1.1 — Audio engine v1 (both hosts)

- **Spec refs:** [03](../../specs/03-audio-engine.md) (all), [02 §2.2](../../specs/02-song-model.md)
  (time), [01 §1–§4](../../specs/01-architecture.md), [13](../../specs/13-agent-guide.md)
- **Depends on:** 0.3 (Done), 0.4 (trait landed; ADR-0002 Proposed), 0.5 (Done on macOS)
- **Size:** L
- **Branch:** `wp/1.1-audio-engine-v1`

## Goal

Make a song document audible, identically on both hosts: symphonia decoding, a render-plan
compiler, the transport state machine, gain/pan/mute/solo, fades, warp `none`/`beatgrid`, the web
chunk pool and the desktop PCM mmap cache, `EngineHost` in both `packages/platform` adapters, peak
pyramids, meters, an offline renderer, and the conformance suite with golden fixtures.

**Acceptance (from [12](../../specs/12-roadmap.md) WP-1.1):**

1. [03 §5.2](../../specs/03-audio-engine.md) timing targets are met.
2. WASM-vs-native null test ≤ −90 dBFS on the fixtures.
3. No audio-thread allocation (`assert_no_alloc`).
4. 12-track playback has no underruns at the target buffer sizes.

## Approach

### Crate shape

`bragi-engine` stays platform-free and compiles for `wasm32-unknown-unknown`. It owns everything
that decides *what* is audible and *when*; the glue crates only move bytes and samples.

| Crate | Contents |
|---|---|
| `bragi-engine` | `plan` (compiler + plan types), `srcmap`, `transport`, `render` (mixer + fades + limiter), `pcm` (source trait), `chunkpool`, `peaks`, `meters`, `offline`, `engine` (host-shaped facade), `rt` (SPSC ring, fixed state block, allocator guard), `preview` |
| `bragi-engine-native` | symphonia decode, raw-f32 PCM cache + `memmap2`, cpal output, render bin used by the conformance harness |
| `bragi-engine-wasm` | `wasm-bindgen` glue: decode + offline render from a memory buffer, fixed-word state snapshot for the SAB |
| `packages/platform` | the TypeScript `EngineHost` interface plus `WasmEngineHost` and `TauriEngineHost` |

### Render plan

Plan compilation is pure and off the audio thread: `compile(doc, assets, sample_rate)` walks the
sections, converts every clip into absolute output samples through `bragi_model::TempoCtx`, and
produces `Vec<TrackPlan>` of `Segment`s. A segment carries:

- `dst_start..dst_end` in output samples,
- its source window and asset,
- a **piecewise-linear `SrcMap`** from output-sample offset to source-sample position (the
  spec's `src_map`), built from the warp,
- an optional constant `stretch` ratio, pitch in semitones, clip gain, fades, reverse.

`warp: none` becomes one segment at the asset's own rate. `warp: beatgrid` converts its anchors to
absolute samples, splits the clip at anchor breakpoints where the local rate changes, and gives
each piece its own ratio. A piece whose ratio is 1 within `RATIO_EPSILON` stays on the **direct
path** (linear interpolation of the PCM, bit-exact when positions land on whole frames); anything
else drives a `bragi_dsp::stretch::PhaseVocoder` instance that the planner allocates in
`Renderer::prepare`, never in `process`.

The plan is swapped by ownership (`Engine::set_plan`); the old plan is returned to the caller so it
is dropped off the audio thread. Deltas recompile the affected tracks: `Engine::apply_delta`
reuses the unchanged `TrackPlan`s (they are `Clone`) and only recompiles tracks named by the
`EngineDelta` or everything when `requires_full_resync` is set.

### Transport

`Stopped → Playing ⇄ Paused`, `Playing → Looping`, `any → Scrubbing → previous`, plus an
`Auditioning` overlay. The transport is a sample counter plus explicit boundary scheduling:
`next_boundary(block_end)` reports loop wraps and stop points inside a block, so the mixer never
overshoots a loop. A loop wrap crossfades 5 ms (equal-power) from the outgoing tail to the loop
start; seek is applied at the next block boundary (≤ 128 samples = 2.7 ms). Mute/solo changes the
target gain and a 5 ms ramp reaches it. The playhead *is* an integer sample counter, so drift is
zero by construction (proved by a 10-minute test).

### Real-time safety

- `Renderer::process` uses only pre-allocated scratch buffers, iterates borrowed plan data, and
  reads PCM through `&dyn PcmSource` / `&ChunkPool` with no insert.
- `rt::alloc_guard` provides a `TrackingAllocator<A: GlobalAlloc>` and a thread-local `Guard`.
  Debug binaries opt in with `#[global_allocator]`; `Renderer::process` enters the guard. An
  integration test installs the allocator and asserts zero allocations across a long run that
  includes loop wraps, seeks, mute changes and a missing chunk (the guard is a no-op in release,
  and the guard check itself is one TLS read).
- The missing-chunk path increments an underrun counter and pushes an event into a pre-allocated
  fixed-size ring; it never allocates.

### Hosts

- **Web:** `ChunkPool` holds 2 s chunks (96 000 frames × channels × f32) in pre-allocated slots,
  LRU, 256 MB default. The audio side only reads; the control side inserts/evicts and drains a
  fixed-size request ring (prefetch 6 s ahead, 2 s behind). `WasmEngineHost` wraps the generated
  `packages/engine-wasm` module; commands/state use the `rt` SPSC ring and a fixed-word state
  snapshot that the worklet writes with `Atomics.store`.
- **Desktop:** decoded PCM is written once to `<cache>/pcm/<assetHash>.f32` (raw interleaved f32,
  48 kHz) and read through a `memmap2` mapping; `MmapPcmCache` implements `PcmSource`. cpal output
  runs the engine in the device callback at 64–2048 frames; state goes back at 60 Hz.
- `packages/platform` gains the `EngineHost` interface from 03 §3.3 and both adapters. The web
  adapter uses AudioWorklet + a decoder worker; the Tauri adapter calls the Rust commands.

### Decoding

One symphonia path (`bragi-engine-native::decode`, plus the same helper in the wasm crate),
returning interleaved f32 at the asset's rate. Decoding happens off the audio thread; the result is
either the mmap cache (native) or the chunk pool (web). MP3/AAC/OGG/M4A are symphonia features, not
separate dependencies.

### Peaks, meters, offline render

- `peaks::PeakPyramid` computes min/max pairs at 256, 1024, 4096 and 16384 samples per bin from
  decoded PCM. The serialised form (`peaks/<hash>.bin`) is a versioned little-endian header plus
  levels, which the web host caches in OPFS and the native host on disk.
- `meters` measures per-track peak + RMS over each quantum and publishes them in the state block
  at 60 Hz. Master momentary LUFS and the 64-band spectrum need K-weighting/FFT and are deferred
  to the metering WP (recorded in 15); peak/RMS are the v1 visual contract.
- `offline` renders a tick range (or the whole song) in fixed 512-frame blocks with the `Render`
  stretch tier, sums the tracks, applies the master chain and returns interleaved f32. It is
  deterministic: no randomness, no wall clock, no parallelism in v1.

### Tests and proofs

| Criterion | Proof |
|---|---|
| 03 §5.2 timing | `crates/bragi-engine/tests/timing.rs`: play start (0 samples when cached), seek (≤ 1 block), loop splice sample-exact + 5 ms crossfade, mute/solo within one block with a 5 ms ramp, 10-minute playhead drift (0 samples) |
| Null test | `scripts/conformance.mjs` (`pnpm test:conformance`): builds the native render bin and the wasm package, renders `fixtures/projects/engine-conformance-*.json`, compares WASM vs native and both against `fixtures/audio/golden/*.wav`; fails above −90 dBFS |
| No audio-thread allocation | `crates/bragi-engine/tests/no_alloc.rs`: counting global allocator + guard, long run with 12 tracks, loop, seek and a missing chunk; asserts 0 allocations |
| 12-track underruns | `crates/bragi-engine/tests/stress.rs`: 12 tracks × 60 s at 128 and 256 frames; asserts `underrun_count == 0` and records the realtime factor |
| Unit coverage | `plan` (warp/anchors/fades/pan/solo/section offsets), `transport` transitions, `srcmap` inversion, `chunkpool` LRU + missing, `peaks`, meters, offline render, preview patches, fuzz (random plans never NaN/panic) |

Fixtures: two short projects over the existing CC0 `drums_120.wav`/`tone_440.wav`, plus a golden
32-bit float WAV per project (≤ 1.5 s each). Licence notes go in `fixtures/audio/LICENSE.txt`.

### Debug-build performance

`[profile.dev.package."*"] opt-level = 2` plus explicit `opt-level = 3` overrides for
`bragi-engine` and `bragi-dsp`, because `[profile.dev.package."*"]` does not cover workspace
members. That keeps the conformance and stress tests in debug fast enough to be the gate.

## Spec gaps found (resolved here unless noted)

| Gap | Resolution |
|---|---|
| 03 §4 `TrackPlan` has `mute` but no `solo` | Added; solo is resolved at plan compile time into each track's audible target, and solo changes ramp like mute |
| 03 §4 `src_map: SrcMap` has no shape | Defined as an ordered list of `(dst_offset, src_sample)` breakpoints interpolated linearly; `SrcMap::src_at` is the only mapping used by the renderer |
| 03 §4 says "warp `none`/`beatgrid`" but not how a beatgrid becomes samples | Anchors are converted to absolute output samples; the clip is split where the local rate changes; sub-1e-6 rate changes are coalesced |
| 03 §5.1/§5.2 loop crossfade shape unspecified | Equal-power, exactly 5 ms (`LOOP_FADE_MS`), applied *after* the sample-exact wrap point |
| 03 §5.3 `PreviewPatch` list has no payload schema | v1 implements `trackGain`, `trackPan`, `trackMute`, `clipOffset`, `moveSection`; `fxParam` and `macro` validate but are no-ops until WP-2.3 |
| 03 §5.4 audition | Two plan slots, 30 ms equal-power crossfade at the same playhead; up to 4 plans kept warm |
| 03 §3.1 says PCM chunks are 2 s / 96 000 frames but the pool is "256 MB" | Sizes are constructor parameters; defaults are 2 s and 256 MB, and the chunk count follows from them |
| 03 §10 master "momentary LUFS + 64-band spectrum" | Deferred (needs K-weighting/FFT); peak/RMS ship and the state block has room for the rest (Q26) |
| 03 §9 offline render block size / thread pool | Fixed 512-frame blocks, single-threaded in v1 (rayon per-track stays WP-1.11's concern) |
| 03 §7 sample rate | Engine and assets are 48 kHz; the web host asks the AudioContext for 48 kHz and resampling on output stays a host concern (Q27) |
