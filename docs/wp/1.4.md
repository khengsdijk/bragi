## Goal

`analysis.structure`: section boundaries, functional labels (`SectionKind`), per-section confidence and
`repeatGroup`, on the WP-0.7 worker framework, plus the structure gates in the WP-1.2 eval harness.

**Acceptance (from [12](../../specs/12-roadmap.md)):** eval gates (boundary hit-rate >= 0.70, label
accuracy >= 0.60); `repeatGroup` correctly groups choruses on >= 80 % of eval songs with >= 2 choruses.

## Honest constraints

- No CUDA, no eval set (Q32). The gates are **machinery plus synthetic proof**; against the real set they
  stay `PENDING`. Synthetic songs are generated from known section plans, so they prove the metrics, the
  pipeline wiring and the repetition logic, never real-music accuracy. Nothing is fabricated.
- The v1 implementation is **weight-free** (see Decision), so it can decide the gate once the set exists
  and needs no `BRAGI_TEST_WEIGHTS` tests.

## Model decision (ADR-0010)

04 §5.2 asks for "an All-In-One-class model or a boundary model + label classifier". Findings:

| Candidate | Code | Weights | Verdict |
|---|---|---|---|
| All-In-One (`mir-aidj/all-in-one`, `allin1`) | MIT | trained on the Harmonix Set; **no weights licence is stated** anywhere in the repo (treated as *unclear*) | not integrated. Also drags in `natten` (CUDA/CPU build friction), `demucs`, `madmom` (BSD code; its own models are non-commercial but unused), `librosa`, `hydra` |
| Boundary model + classifier trained by us | n/a | no permissive labelled data in this environment | out of scope |
| **Self-similarity + novelty segmentation + repetition grouping on beat-synchronous chroma/timbre** (Foote 2000, McFee & Ellis / Serra et al. lineage) | ours (NumPy/SciPy, already deps) | none | **chosen for v1**; `stageVersion` `structure@ssm-novelty-1` |

The classical method is exactly the machinery 04 §5.2 prescribes for `repeatGroup` ("self-similarity
matrix of beat-synchronous chroma + embeddings"), and the label step goes through a model-vocabulary ->
`SectionKind` mapping (`config/structure_labels.json`) so an All-In-One-class model can replace the
*segmenter and labeller* later without touching grouping, snapping or the contract (Q60). No new
dependency is added; ADR-0010 records the decision.

## Approach (`services/workers/analysis/src/bragi_analysis/`)

```
structure/
  features.py   beat-synchronous chroma + timbre (log-mel DCT) + RMS energy, from an STFT
  novelty.py    self-similarity matrix, Foote checkerboard novelty, peak picking
  snap.py       boundaries -> downbeats -> 4-/2-bar phrase grid (within +-1 beat)
  grouping.py   repeat groups: aligned segment similarity + average-linkage clustering
  labels.py     functional labels in the model vocabulary + taxonomy mapping + start/end merge
  pipeline.py   analyse(mono, sr, beats, downbeats) -> StructureResult
capabilities/structure.py   CAPABILITY analysis.structure, ParamsModel, run()
config/structure_labels.json
evaluation/{synthetic_songs,structure_eval}.py   generated songs; boundary/label/repeat scoring
```

- Inputs: `assets.source` (audio) and optional `blobs.rhythm` (a `RhythmResult`; the orchestrator does not
  wire blobs yet, Q33). Without it the capability tracks beats itself with the `rhythm` tracker selection.
- Output `blobs.result`: `StructureResult` (schema already exists from WP-0.2; no schema change expected).
- Every section gets a `repeatGroup` letter (A, B, ... by first appearance); a unique section has its own
  letter. `lowConfidence` when no convincing novelty peak exists or the beat grid itself is low-confidence.
- Metrics: boundary hit-rate = `mir_eval.segment.detection` recall at +-3 s (04 §8), precision/F reported;
  label accuracy = duration-weighted agreement of `SectionKind`; repeat-group check = all reference
  choruses map (max overlap) to estimated sections sharing one group that no non-chorus reference section
  maps to.
- Manifest: `labels.sections` (optional) is a text file, one section per line `<start> <end> <kind>`.
  Structure gates are decided over the tracks that have it.

## Test plan

| Layer | What |
|---|---|
| features/novelty | known-structure synthetic song: novelty peaks near the true boundaries |
| snap | hand-built beat/downbeat lists: downbeat snap, 4-bar and 2-bar phrase snap, no snap beyond +-1 beat |
| grouping | repeated sections share a group; different material does not; length mismatch does not group |
| labels | taxonomy mapping (`inst -> interlude`, `break -> breakdown`, `start/end` merged), heuristics on hand-built segment stats |
| pipeline | synthetic songs: boundary hit-rate, label accuracy, chorus grouping; output validates against the schema, sections tile `[0, duration]` |
| capability | `run()` with a `FakeContext` on a generated WAV (needs ffmpeg), with and without `blobs.rhythm`; no-beat/short/silent audio publishes one section with `lowConfidence`, never a failure |
| metrics/harness | `mir_eval` boundary values on hand cases; gate semantics PASS/FAIL/PENDING; report renders the structure section |
