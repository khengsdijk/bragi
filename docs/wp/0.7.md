# WP-0.7 — Backend & worker skeleton

- **Spec refs:** [05](../../specs/05-backend-and-jobs.md) (all), [01 §1, §4, §6, §8](../../specs/01-architecture.md),
  [13](../../specs/13-agent-guide.md)
- **Depends on:** 0.2 (Done — job/event/error envelopes and the generated TS/Python models exist)
- **Size:** L
- **Branch:** `wp/0.7-backend-worker-skeleton`

## Goal

Stand up the whole async spine of Bragi end to end, with one executable integration proof:

```
HTTP (login · upload · submit)  ──►  NATS JetStream (JOBS)  ──►  Python worker  ──►  NATS (EVENTS)  ──►  WebSocket
        │                                    │                                              │
        └────────────── OpenTelemetry: one trace across all three hops ─────────────────────┘
```

**Acceptance (from [12](../../specs/12-roadmap.md)):** an integration test (docker compose) logs in,
uploads a file, submits an `echo` job, receives `progress` + `completed` over WebSocket, and shows
one trace spanning API → NATS → worker.

## Shape of the work

Three new pieces plus infra, consuming (never re-inventing) the WP-0.2 contracts:

### 1. `services/api` (TypeScript, Fastify)

| Area | What ships | Spec |
|---|---|---|
| Config | zod-validated env at boot, every var defaulted, `.env` optional | 01 §8 |
| Auth | **Better Auth**: email magic link (SMTP → Mailpit locally) + GitHub OAuth (implemented, **untestable here**) | 05 §8 |
| DB | `pg` pool, a tiny ordered SQL migration runner, `migrations/001_init.sql` with every table in 05 §5 | 05 §5 |
| Assets | `POST /assets/presign`, `POST /assets/{hash}/complete` (real size + SHA-256 check), `GET /assets/{hash}/url` | 05 §2, §6 |
| Jobs | `POST /jobs`, `GET /jobs/{id}`, `DELETE /jobs/{id}` (cancel via KV) | 05 §2, §4.4 |
| NATS | idempotent `JOBS` (work-queue) + `EVENTS` (limits 24 h) streams, `cancel` KV bucket | 05 §4.1 |
| WebSocket | `GET /v1/ws`, session-authenticated on connect, `sub`/`unsub`, fans `events.*` out as the 05 §3 message shapes | 05 §3 |
| DAG | the 04 §2 analysis DAG + a pure `readyStages()` executor | 05 §4.4, 04 §2 |
| Orchestrator | `api-orchestrator` entrypoint: durable consumer on `events.job.>`, records state, enqueues ready dependents | 05 §1, §4.4 |
| Telemetry | OTel SDK + auto-instrumentation; `traceparent` into every `JobRequest` | 05 §11 |

### 2. `services/workers/bragi_common` (Python framework)

| Module | Responsibility |
|---|---|
| `config.py` | pydantic-settings, every var defaulted |
| `telemetry.py` | OTel provider; extract `traceparent` → child span (producer → consumer) |
| `s3.py` | content-addressed `sha256/<aa>/<bb>/<hash>` put/get, hash-verified download |
| `cache.py` | `job_results` result cache (asyncpg) |
| `cancel.py` | NATS KV `cancel.<jobId>` flag, checked between chunks |
| `progress.py` | ≤ 2 reports/s throttle, JetStream in-progress ack every 10 s |
| `protocol.py` | `Outputs` (= generated `JobOutputs`), the capability registry |
| `context.py` | `JobContext` handed to `run(job, ctx)` |
| `worker.py` | pull loop: interactive subject first, cache hit → immediate `completed`, run, upload, ack / NAK-retry |

Plus `services/workers/analysis`'s **`echo`** capability (`CAPABILITY = "echo"`), the executable
capability used by the acceptance test.

### 3. Infra (owned by this WP)

`infra/docker-compose.yml` grows **additively**: an `api` service (`api-http` + `api-orchestrator`),
a CPU `worker` service, and a dev-only `jaeger` service (OTLP receiver + trace query API) so the
trace is *visible* locally. Postgres/MinIO/NATS/Mailpit are untouched. Only
`docker compose up -d --build api worker jaeger` is ever run.

## Spec gaps found (recorded here; edits in the specs in the same branch)

- 05 §3 `job.progress` carries `stage`, `job.partial` carries `index`, but the WP-0.2 `JobEvent`
  envelope has neither. The gateway derives `stage` from the job's capability and `index` from a
  per-job counter; noted in 05 §3.
- 05 §5 `users` columns are the *application* columns; Better Auth owns its own `user`/`session`/
  `account`/`verification` tables, so 05 §5 gets one line pointing at them.
- 02 §2.1 does not list an ID prefix for assets (`sha256:…`) or library items; left as-is.
