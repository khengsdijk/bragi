- **Branch:** `wp/1.6-workers-embeddings-tags`

## Goal

Five analysis capabilities on the WP-0.7 worker framework — `analysis.stem_activity`,
`analysis.embed_full`, `analysis.section_embed`, `analysis.stem_embed` and `analysis.tag` — the
controlled `packages/schemas/analysis/taxonomy.json`, the zero-shot descriptor path, the MLP-head
tagging scaffold with its training script and reproducible notebook, and the pgvector write path.
Everything must run weight-free on CPU so `pnpm verify` stays fast and torch-free.

**Acceptance (from [12](../../specs/12-roadmap.md)):**
1. Top-3 genre agreement with a hand label ≥ 0.70.
2. The text query `"drums"` ranks drum stems above other stems for ≥ 90 % of eval songs.

Both criteria need labels and audio that **do not exist** ([15](../../specs/15-open-questions.md)
Q32/Q17): criterion 1 needs the owner's eval set *and* trained MLP heads (no labelled training data
here); criterion 2 needs the eval set's per-stem references. They ship as **machinery + synthetic
proof** and stay **PENDING** against the real set. The `"drums"`-ranking *metric* is proven on a
synthetic multi-stem fixture through the fallback embedder.

## Environment constraints (stated up front)

- macOS 15 / arm64 (Apple M2 Pro). **No CUDA GPU.** Everything runs on CPU (13 §3).
- **No eval set** (`fixtures/eval/manifest.json` lists no tracks), **no training data** and **no
  downloadable model weights** (Docker Hub / Hugging Face pulls are blocked here). No accuracy
  number is claimed for any real song.
- **No weights are committed or downloaded.** CLAP is behind a hash-pinned loader that refuses a
  missing or unverified checkpoint; the fallback embedder needs nothing.
- No copyrighted audio; every fixture is generated by the test (13 §1.7).

## Approach

### Contracts (schema-first)

The WP-0.2 blobs already exist and fit: `StemActivityResult` (`common.md` §5.4), `EmbeddingResult`
(§6.1) and `TagResult` (§6.2). Two additive fields are missing: `EmbeddingResult.lowConfidence` and
`TagResult.lowConfidence` (04 §10 publishes a low-confidence flag for a degraded stage; `rhythm`,
`structure` and `harmony` already have it, WP-1.5 precedent). They are added schema-first and
regenerated; nothing else in the schemas changes.

`packages/schemas/analysis/taxonomy.json` is a **data file** (not a `*.schema.json`), so the
codegen's schema walk ignores it. `packages/schemas/codegen/gen.mjs` gains one output: it copies the
taxonomy into `bragi_analysis/config/taxonomy.json`, the copy the worker actually loads at runtime
(the container image holds only `services/workers`, never `packages/schemas`). The copy is
generated and `pnpm schemas:check` fails if it drifts — the same pattern as every other generated
artifact. The mirror is loaded with `importlib.resources`, like `config/structure_labels.json`.

### Decision: CLAP as the target, a deterministic concept-basis fallback for CI (ADR-0011)

04 §6.1 bans any embedding model that is not a joint audio–text space, because text search and
zero-shot tagging depend on it. The v1 target is **LAION-CLAP `laion/larger_clap_music`**
(512-d, Apache-2.0 weights, MIT code). Its weights are not downloadable here and torch is not in the
default environment, so:

- `embedding/protocol.py` defines an `Embedder` protocol (`model`, `dim`, `embed_audio`,
  `embed_texts`) and `select()`.
- `embedding/clap.py` is `CLAPEmbedder`: it loads a SHA-256-pinned checkpoint from
  `BRAGI_CLAP_CHECKPOINT` / `BRAGI_MODELS_DIR`, refuses anything unverified, imports `torch` +
  `transformers` lazily and **never downloads**. It is un-runnable here and is marked `PENDING`.
- `embedding/fallback.py` is `FallbackEmbedder` (`model` `bragi-concept-basis-1`): a deterministic,
  NumPy-only **concept basis**. Each taxonomy concept owns a fixed pseudo-random unit vector in
  R^512 (seeded from the concept id) and a hand-written audio profile over interpretable DSP
  descriptors (band energies, onset/transient strength, spectral flatness, centroid, dynamic range).
  An audio vector is the L2-normalised activation-weighted sum of concept basis vectors; a text
  vector is the same sum for the concepts its keywords hit. In 512-d the basis vectors are
  near-orthogonal, so cosine similarity reflects **concept overlap** — enough to make
  `"drums"` rank a drum-like stem first and to prove the machinery, *not* a claim about real music.
  It is documented everywhere as a CI/runtime fallback, never as the product semantics.

The real accuracy gates need the CLAP checkpoint, the eval set and trained heads.

### `analysis.stem_activity` (§5.4) — fully weight-free

Inputs: the separated stems (`assets.stem_<role>`). Decode each to mono at 22 050 Hz, compute RMS on
a **250 ms hop**, gate at **−45 dBFS**, and join open hops into `active[] {startSec, endSec}`
runs (runs shorter than one hop are merged; a gap shorter than the hop is closed so a gated stem does
not shatter into click-tracks). Per section (from an optional `blobs.structure`), `presence` is the
share of in-section hops whose gate is open (0..1). No structure blob ⇒ `presence: []` (the schema
allows it) and the capability needs no sibling. Silent stems publish `active: []`, `presence` all
zeros — never a failure (04 §1.3, §10).

### `analysis.embed_full` / `section_embed` / `stem_embed` (§6.1)

One `embedding` package, three thin capabilities:

| Capability | Input | Pooling |
|---|---|---|
| `embed_full` | `assets.source` | whole song |
| `section_embed` | `assets.source` + `blobs.structure` | within each section span |
| `stem_embed` | `assets.stem_<role>` (+ optional `blobs.stem_activity`) | over the stem's active regions |

`embedding/windows.py` implements the 10 s window / 5 s hop rule and the overlap-weighted pooling:
each window's vector is weighted by the fraction of it inside the requested spans (all windows for a
song), summed, then L2-normalised. That one primitive serves "pool over the whole song", "pool within
the section" and "pool over the stem's active regions". Windows are computed over the whole decoded
span so the result does not depend on where a slice happens to start. Digital silence yields a
zero-norm pool; the pool then returns a fixed canonical unit vector with `lowConfidence: true`,
because a silently-emitted zero vector would not be L2-normalised.

`model` in the blob is the embedder id (`laion-clap-music-1` / `bragi-concept-basis-1`); the
capability's `stageVersion` mirrors it. `scopeRef` is the section index for sections and the stem
role for stems, absent at song scope (the structure blob carries no section ids; indices are the
stable handle — recorded below as a gap).

### `analysis.tag` (§6.2)

- **Taxonomy.** `taxonomy.json` holds ~150 hierarchical genres (`electronic > house > deep house`),
  ~60 moods, ~80 instruments, ~200 production descriptors and decade eras. `tagging/taxonomy.py`
  validates it on load: unique ids, genre parents exist and are acyclic, optional-prompt defaulting,
  minimum counts. `config/tag.toml` holds the top-k limits (genres ≤ 3, moods ≤ 4, descriptors ≤ 6,
  instruments ≤ 8, eras ≤ 1) and a minimum score.
- **Zero-shot path.** `tagging/zeroshot.py` scores every taxonomy label by the cosine of the audio
  song vector against the label's text template. This is the *descriptor* method 04 §6.2 names, and
  the fallback classifier for every category until heads exist.
- **MLP heads.** `tagging/heads.py` loads one small NumPy MLP per category from `BRAGI_TAG_HEADS`
  (a `.npz` of float32 weights, softmax over the category's labels). Present ⇒ heads classify
  genre/mood/instrument and zero-shot still does descriptors and era. Absent ⇒ zero-shot for all,
  `lowConfidence: true`. `services/workers/embed/training/` holds `train_heads.py` and
  `heads.ipynb`, which train exactly those heads on CLAP embeddings + MTG-Jamendo (CC) labels.
  They are **not run here** (no dataset, no weights); the exact commands and the dataset's licence
  are owner actions.
- **Input reuse.** When `blobs.embed_full` is passed, the song vector is reused instead of
  recomputed.

### pgvector storage (05 §5)

Migration 001 already creates the `embeddings` table; its comment defers the indexes to the WP that
populates it. A new migration `002_embeddings_hnsw` adds the HNSW index on `embeddings.vec` and a
lookup index on `(asset_hash, scope, scope_ref, model)`. The write path is
`embedding/store.py`: an `EmbeddingStore` protocol,`PgVectorStore` (asyncpg, `$n::vector` from a
text literal) and a module-level `store_factory` that builds a short-lived pool from
`Settings.database_url`. The capabilities persist only when the params flag `storeEmbeddings` is
true (default false), so the CPU gate never touches Postgres; the store is exercised with a fake.

### Module layout (`services/workers/analysis/src/bragi_analysis/`)

```
embedding/
  protocol.py   Embedder protocol, select(), STAGE_VERSIONs
  windows.py    10 s/5 s window plan, overlap weights, weighted pool + L2 normalise
  fallback.py   FallbackEmbedder: concept basis + DSP profiles (NumPy only)
  clap.py       CLAPEmbedder: hash-pinned LAION-CLAP checkpoint, lazy torch, no download
  pipeline.py   windowing/pooling -> EmbeddingResult per scope
  store.py      EmbeddingStore protocol, PgVectorStore, store_factory
tagging/
  taxonomy.py   load + validate config/taxonomy.json
  zeroshot.py   cosine over taxonomy prompts
  heads.py      MLP head loading + forward (NumPy), the neural seam
  pipeline.py   build_result: heads when present, zero-shot otherwise -> TagResult
capabilities/
  stem_activity.py  embed_full.py  section_embed.py  stem_embed.py  tag.py
config/
  taxonomy.json  (generated from packages/schemas/analysis/taxonomy.json)
  tag.toml       (top-k limits)
```

`embedding/*` and `tagging/*` import no I/O, ffmpeg or torch at module scope, so the numeric cores
are unit-tested on arrays directly.

## Spec gaps found

1. **`EmbeddingResult` and `TagResult` had no `lowConfidence`** while 04 §10 and the sibling
   schemas do. Added schema-first, like WP-1.5's `HarmonyResult`.
2. **The structure blob carries no section ids**, so `section_embed`'s `scopeRef` is the section
   *index*. Fine while sections are a flat ordered list; recorded as a question for the day
   sections get stable ids.
3. **`stem_activity` and `stem_embed` want a `structure`/`stem_activity` blob** that the
   orchestrator does not wire yet (Q33). Both work without it and degrade to whole-song/whole-stem.
4. **`taxonomy.json`'s home (Q46).** The worker cannot read `packages/schemas` at runtime, so the
   file is authored there and **generated into** the worker package by the codegen. The
   model-vocabulary → `SectionKind` mapping stays worker-local (`config/structure_labels.json`): it
   is a segmenter adapter, not part of the tag vocabulary. Q46 is answered with that split.
5. **Training data has no home.** MTG-Jamendo (CC) and the exact training commands are documented,
   but nothing downloads or trains here; the trained heads, their licence and the per-label
   threshold calibration are the owner's.
6. **The CLAP checkpoint hash is not verifiable here** (no download). The pin records the model,
   source, licences and revision; the SHA-256 and the pinned commit are owner actions, and the
   loader refuses an unverified checkpoint until they are filled in.
7. **"Pool over the stem's active regions"** is implemented as overlap-weighted window pooling over
   the whole stem (windows outside the active regions get zero weight), which keeps the 10 s/5 s
   window grid stable instead of re-windowing each region. Recorded as a question.
8. **`embeddings` is keyed by asset with no user column** (05 §5); the write path inserts only the
   vector rows. Access control stays with `user_assets`/`library_items` joins, unchanged.

### Proofs (measured, macOS 15 / arm64, CPU)

- `"drums"` ranking on the synthetic quartet: cosine to the drum stem **0.256** vs **0.042** for the
  next stem; `"bass"` ranks the bass stem **0.372** vs 0.081. (Fallback embedder, labelled synthetic.)
- `stem_activity`: a full-scale 100 Hz sine reads **−3.01 dBFS** at the 250 ms hop; a 250 ms gap is
  closed, a 500 ms gap is not; a sub-hop run is dropped.
- Tests: **323 passed, 2 skipped** (the weights-gated Beat This! and separation tests). `ruff check`,
  `ruff format --check`, `mypy --strict` and `pnpm schemas:check` are clean.

### Deviations

- `EmbeddingResult` and `TagResult` gained `lowConfidence` (04 §10 applies to every stage; `rhythm`,
  `structure` and `harmony` already had it). Added schema-first and regenerated.
- 04 §6.2's "~150 genres" ships as **211** (a superset; the spec note records the real counts).
- `taxonomy.json` is authored in `packages/schemas` and **generated into** the worker by the
  codegen (the container ships only `services/workers`); the `structure` label mapping stays
  worker-local — this answers Q46.
- `embed_*`/`tag` select the embedder with `auto` ⇒ CLAP only when a verified checkpoint exists,
  else the fallback; the fallback's model id and `lowConfidence` make the distinction visible.

### Deferred / not done

- Everything needing real weights, data or the eval set: the CLAP pin (Q68), trained heads and the
  top-3 genre gate (Q67), the `"drums"` gate on real songs, and any accuracy claim.
- `section_embed`'s `scopeRef` is the section **index** (the structure blob has no ids, Q66).
- The stem-active-region pooling is overlap-weighted whole-stem windows, not re-windowed regions,
  and the fallback defines no era concepts (Q69).
- The pgvector write path is worker-side and behind a flag; `/search`'s query contract and who owns
  the write are open (Q70).
- Not exercised: the NATS end-to-end path with the new capabilities, the worker `Dockerfile`
  (`--extra clap` was never built), a live Postgres/pgvector insert, and anything off macOS 15 /
  arm64 (Q11).
