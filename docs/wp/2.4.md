# WP-2.4 — Paint brushes (instant set)

- **Spec refs:** [07 §4.4, §5, §10 check 3](../../specs/07-song-canvas.md), [02 §3.7–3.8](../../specs/02-song-model.md), [03 §6.1](../../specs/03-audio-engine.md)
- **Depends on:** 2.3 (Done)
- **Size:** M
- **Branch:** `wp/2.4-brushes`

## Goal

Paint on the ribbons. A stroke defines a region (time × the tracks it touched) and a strength (pen
pressure, scroll wheel while painting, or the brush-size slider, shown as stroke opacity). The
instant brushes commit one op batch on stroke end: Space, Warmth, Brighter/Darker, Lo-fi,
Louder/Quieter, Filter sweep, Remove. The ✨ brushes (Shimmer, More drums, Riser/Impact) are jobs and
arrive with WP-2.7; they are not shown here.

**Acceptance (12):** 07 §10 check 3 (an instant brush stroke produces one commit with automation
points whose ramps are ≥ 50 ms at the edges). Pen pressure works in Chromium and Safari with pointer
events.

## Approach

### A. Brush model (pure TS, `features/brushes/`)

- `strokeRegion(stroke, layout)` → `Region` (ticks snapped to 1/16 beat, the touched track ids).
- `strokeStrength(samples)` → 0..1 from pressure (pointer `pressure`, `0.5` for a mouse), the wheel
  delta while painting, or the size slider.
- Per brush, `brushBatch(doc, region, strength, direction)` → one `OpBatch`:
  - **Space / Warmth / Brighter / Darker:** ensure the track's `macroOwned` fx for that macro (the
    WP-2.3 `macroBatch` at value 0 creates them), then `automation.set` on each driven param
    (`fx:<fxId>/<param>`): inside the region the macro curve at `strength` (signed for
    Darker), outside the current value, with **≥ 50 ms linear ramps** at both edges. Lanes are
    section-relative (02 §3.8), so a region spanning sections writes one lane per section.
  - **Louder / Quieter:** `track:<id>/gainDb` automation, ± up to 12 dB × strength, same ramps.
  - **Filter sweep:** a `filter` fx (low-pass) per track + `cutoffHz` automation following the
    stroke direction (rising or falling across the region, exponential in Hz).
  - **Lo-fi:** 07 §4.4 says clip-level `lofi` fx. The engine still ignores clip-level fx (deferred
    in WP-2.3). **Decision:** a track `lofi` fx at `mix = 0` with `mix` automation up to the strength
    inside the region (≥ 50 ms ramps) — audibly the same, no engine change; recorded as a deviation
    and a spec note in 07 §4.4.
  - **Remove:** `region.clear` (the model adds the fades).
  - Existing automation on the same target is merged: points inside the region are replaced, points
    outside kept (unit-tested).
- Unit tests per brush with the real model: one batch, applies cleanly, undo deep-equal, ramp
  lengths ≥ 50 ms at the tempo map's local tempo, region snapping, strength mapping.

### B. Painting UI

- A brush palette in the tools area (07 §1) with the seven instant brushes, a strength slider and a
  direction toggle where it applies; keyboard: pick a brush, select a region (task-2.2 keyboard paths
  and 11 §6.2 "select a region, then Apply brush… from the menu"), Apply brush… in the section menu
  and the command palette.
- Painting on the canvas: pointer events with `pressure`/`pointerType`; the renderer draws the stroke
  (opacity = strength) over the touched ribbons; the stroke previews through `startGesture` (the
  document copy; audio follows) and commits once on pointer up with label "Space on Drums, bars 9–12".
  Escape cancels.
- Tests: Vitest for the controller (stroke → region → one commit); a Playwright test on the demo page
  that paints with the mouse and with a synthetic pen (`pointerType: "pen"`, varying `pressure`) in
  Chromium and WebKit, asserting one commit and ramp lengths; axe with the palette open.

### C. Verification (Opus)

Live: paint Space on a stem of a real song while playing, undo, Remove a region; listen
(MANUAL_CHECKS); Chromium, Firefox, WebKit e2e.
