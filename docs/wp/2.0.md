# WP-2.0 — Single-user mode

- **Spec refs:** [05 §2, §3, §8](../../specs/05-backend-and-jobs.md), [ADR-0014](../../specs/decisions/ADR-0014-single-user-mode.md), [13 §9](../../specs/13-agent-guide.md)
- **Depends on:** 0.7 (Done), 1.10 (Done for the web flow)
- **Size:** S
- **Branch:** `wp/2.0-single-user-mode`

## Goal

Running Bragi locally needs no sign-in. With `BRAGI_AUTH_MODE=single-user` the API signs every
request and WebSocket in as one owner account, the welcome page goes straight to the drop zone,
and the desktop app talks to the local API without the bearer/PKCE flow. Multi-user mode (magic
link, GitHub OAuth) is unchanged and stays the default for compose/hosted.

## Approach

### API (`services/api`)

| Piece | Where | What |
|---|---|---|
| Config | `src/config.ts` | `authMode: "single-user" \| "multi-user"` (env `BRAGI_AUTH_MODE`, default `multi-user`), `ownerEmail` (`BRAGI_OWNER_EMAIL`, default `owner@bragi.local`), `ownerName` (`BRAGI_OWNER_NAME`, default `Owner`), `allowRemoteSingleUser` (`BRAGI_ALLOW_REMOTE_SINGLE_USER`, booleanish, default false) |
| Loopback guard | `src/auth/single-user.ts` (`assertSafeBinding(config)`), called from `server.ts` before `listen` | In single-user mode, `API_HOST` must be loopback (`127.0.0.0/8`, `::1`, `localhost`); `0.0.0.0`/`::` and any other address are refused unless `allowRemoteSingleUser`. The refusal throws an error naming the host and the override; the override logs a `warn` |
| Owner account | `src/auth/single-user.ts` (`ensureOwner(pool, config)`), called once at boot in `server.ts` | `INSERT … ON CONFLICT (email) DO NOTHING` into Better Auth's `user` table, then `SELECT`; idempotent across restarts |
| Session resolver | `src/auth/session.ts` (`createSessionResolver`) | **The one place sessions are resolved.** `AppContext.sessions.resolve(headers)` returns the owner `Session` in single-user mode, and Better Auth's `getSession` in multi-user mode. `routes/guards.ts` `requireSession` and `ws/gateway.ts` call it instead of Better Auth directly. Ownership checks are untouched: there is still a `user.id` |
| Mode endpoint | `src/routes/auth-routes.ts` | `GET /v1/auth/mode` → `AuthModeResponse` (`{ mode, user }`, `user` is `null` in multi-user mode without a session). Registered as a static route, so it wins over the Better Auth `/v1/auth/*` catch-all |
| Meta | `src/routes/meta.ts` | `features.singleUser` mirrors the mode |
| Dev launcher | `scripts/dev-backend.mjs` | Defaults `BRAGI_AUTH_MODE=single-user` and `API_HOST=127.0.0.1` unless set |
| Compose | `infra/docker-compose.yml` | Passes `BRAGI_AUTH_MODE` (default `multi-user`), the owner vars and `BRAGI_ALLOW_REMOTE_SINGLE_USER` through. Inside a container the API binds `0.0.0.0`, so single-user in compose needs the override (documented) |

In single-user mode the Better Auth routes stay mounted (harmless; nothing in the UI uses them).
The synthetic session is `{ id: "single-user", expiresAt: <far future> }`.

### Schema (first)

`packages/schemas/api/auth-mode.schema.json` → `AuthModeResponse`
`{ mode: "single-user" | "multi-user", user: { id, email, name } | null }`, plus an example, then
`pnpm schemas:gen`.

### Client

| Piece | Where | What |
|---|---|---|
| api-client | `packages/api-client/src/index.ts` | `AuthMode` type and `getAuthMode(): Promise<AuthModeResponse>` |
| Welcome page | `packages/app/src/features/library/components/LibrarySection.tsx` | A TanStack Query on `getAuthMode`; the sign-in form renders only when `mode === "multi-user"`. In single-user mode the drop zone is usable immediately; nothing else changes |
| Desktop | `packages/app/src/features/analysis/api/host.ts` | Unchanged credential logic; in single-user mode the API needs no credential at all, so the desktop `"bearer"` host works against the local API. Q81 stays open for hosted |

### Tests

- **API unit** (`services/api/src/__tests__/`): config parsing for the four new vars; loopback
  guard (127.0.0.1, ::1, localhost accepted; 0.0.0.0, ::, 192.168.1.10 refused; override
  accepted); session resolver in both modes (single-user returns the owner with no cookie;
  multi-user delegates and returns `undefined` with no cookie); `GET /v1/auth/mode` in both modes
  via `app.inject`; `ensureOwner` idempotency against a fake pool.
- **Integration** (`services/api/test/integration/`): `startStack(otelPort, { authMode })`.
  `analysis-flow` runs in single-user mode with **no** login (plain requests). The WP-0.7
  `acceptance` test keeps the magic link and runs against a `multi-user` stack, so that path does
  not rot.
- **E2E** (`apps/web/e2e/upload-flow.spec.ts`): no sign-in step in single-user mode (the default
  stack); the keyboard-only path tabs straight to the drop zone; axe stays.
- **Live:** `pnpm dev:backend` + `pnpm dev:web`, open the app in a browser, no sign-in, drop a
  song, playable canvas.

## Out of scope

Desktop PKCE / bearer tokens (WP-2.9, multi-user only), hiding Better Auth routes in single-user
mode, account switching.

## Outcome (2026-10-19)

**Done.** Implemented by two DeepSeek V4.1 Flash agents (API half, client half), reviewed and
verified live by the orchestrator.

- API: `BRAGI_AUTH_MODE` / `BRAGI_OWNER_EMAIL` / `BRAGI_OWNER_NAME` /
  `BRAGI_ALLOW_REMOTE_SINGLE_USER` in the zod config; `ensureOwner` (idempotent upsert into
  Better Auth's `user`); `createSessionResolver` in `auth/session.ts` is the one seam that both
  `requireSession` and the WebSocket gateway use; `assertSafeBinding` refuses a non-loopback
  `API_HOST` in single-user mode before `listen` (logged, exit 1) unless the override is set (then
  a warning); `GET /v1/auth/mode` (`AuthModeResponse`, schema first); `features.singleUser` in
  `/v1/meta`. `pnpm dev:backend` defaults to single-user on `127.0.0.1`; compose stays
  multi-user.
- Client: `ApiClient.getAuthMode()`; the welcome page renders the sign-in form only in
  multi-user mode; desktop needs no credential against a local single-user API (Q81 resolved for
  local use, still open for hosted / WP-2.9).

**Verified (M2 Pro, macOS 15 / arm64):**

- `pnpm verify` green on the merged branch.
- Unit: config, loopback table, guard refusal/override, owner upsert, resolver in both modes,
  `/v1/auth/mode` in both modes, a guarded route 200 with no cookie in single-user and 401
  `AUTH_REQUIRED` in multi-user; welcome-page component tests for both modes.
- `BRAGI_STACK=local pnpm test:integration`: **2/2 passed** — `analysis-flow` in single-user mode
  with no login, and the WP-0.7 magic-link `acceptance` test against a multi-user stack.
- `pnpm test:e2e:flow` against `pnpm dev:backend` + the Vite dev server, no sign-in: **Chromium,
  Firefox and WebKit 2/2 each** (upload, playable canvas, every stem soloable, reload, axe, the
  keyboard-only path). `/v1/auth/mode` through the Vite proxy returned the owner. Browser timings
  (not a benchmark; three Rust builds were running on the same machine): file chosen → playing
  4.3–6.1 s; stems in the document 19.6 s (Chromium, warm cache), 37.9 s (WebKit), 119.6 s
  (Firefox, cold, under load).

**Found and fixed while verifying:** the analysis worker could fail `loudness_energy` with
"partially initialized module 'torch'": SciPy's array-API check probes `sys.modules["torch"]` while
separation is importing torch on another thread. The worker now imports torch on the main thread
before any job (`bragi_analysis/worker.py`). The e2e spec lost its `page.goto` together with the
sign-in helper, so its "no sign-in form" check passed on a blank page; fixed.

**Not verified:** the compose `api` image in single-user mode (Docker Hub pulls are blocked here,
as in WP-0.7), the desktop app against the local API (Tauri e2e not run for this WP), and the
multi-user welcome page in a browser (covered by component tests only).
