# WP-0.6 — Design tokens & base components

- **Status:** built on `wp/0.6-design-tokens` (2026-10-18) — see [Outcome](#outcome-as-built-2026-10-18) at the end for what changed against this plan.
- **Spec refs:** [11 §3](../../specs/11-ux-and-accessibility.md) (core), 11 §2, §6; [01 §1, §4](../../specs/01-architecture.md); consumers in [07 §1–§4](../../specs/07-song-canvas.md)
- **Depends on:** 0.1 (Done)
- **Size:** M
- **Branch:** `wp/0.6-design-tokens`

## Goal

Finalise Bragi's visual language as data — font, UI colours for both themes, instrument role
colours, section-kind colours and the energy gradient — and ship the accessible base components
every later UI work package builds on, with a component workshop to look at them.

**Acceptance (from [12](../../specs/12-roadmap.md)):**
1. All tokens pass contrast checks (script).
2. Colour-blind simulation snapshots exist.
3. axe passes on all stories.

## Approach

### Tokens: one source, two generated views

`packages/design/tokens.json` is the **only** hand-edited token file. From it:

- `packages/design/tokens.css` is generated (`pnpm --filter @bragi/design tokens:gen`), carrying
  a "generated — do not edit" header. A test regenerates it in memory and fails if the committed
  file differs, so the two can never drift. 11 §3 names both paths, so they stay where the spec
  says rather than moving under a `generated/` directory.
- the PixiJS/Three.js renderers read `tokens.json` directly (exported as `@bragi/design/tokens.json`).

Structure: `font`, `type` (14 px base, ratio 1.2, in `rem` so text scales to 200 %), `space`
(4 px grid), `radius`, `motion` (150/200/250 ms UI, 600 ms lens morph, easings), `size` (hit
targets ≥ 24 px), and per theme (`dark`, `light`): `color` (UI), `role`, `section`, `energy`. A
`contrast` list in the same file declares **which pairings must meet which ratio**; the check
iterates it, so adding a token without a pairing is caught by a test that every colour token is
covered by at least one pairing (or explicitly marked decorative).

Colours are chosen in OKLCH and solved against the constraints below (a throwaway solver, not
committed — the committed artefact is the hex values plus the checks that prove them).

### Contrast check (acceptance 1)

`src/tokens/contrast.ts` implements the WCAG 2.x relative-luminance contrast ratio. The test
asserts every declared pairing in both themes: **4.5:1 for text, 3:1 for UI components and
essential graphics** (11 §6.4, WCAG 2.2 AA 1.4.3 / 1.4.11). Role colours, section fills, energy
stops and the focus ring are checked as graphics against every surface they are drawn on; section
labels are checked as text against their section fill. It runs in `pnpm verify` through the
package's `test` task, and `pnpm --filter @bragi/design tokens:report` prints the full table.

### Colour-blind simulation (acceptance 2)

Machado et al. (2009) dichromacy matrices at severity 1.0 for protanopia, deuteranopia and
tritanopia, applied in linear sRGB. Committed outputs, regenerated and compared by a test:

- `packages/design/snapshots/cvd/<theme>.json` — every role/section/energy entry as simulated hex.
- `packages/design/snapshots/cvd/<theme>.svg` — a swatch sheet (normal + 3 simulations) for
  humans to look at.

Plus a **distinguishability check**: under normal vision and each simulation, every pair of role
colours, of section colours, and every pair of adjacent energy stops must keep a CIEDE2000
difference above a stated threshold. The thresholds are recorded in `tokens.json` (so they are
reviewable data, not magic numbers in a test). Colour is never the only carrier (11 §3): roles
also carry a pattern id in the tokens, which must be unique per role.

### Components

Radix primitives (named in 01 §1, no ADR) via the `radix-ui` umbrella package, styled with CSS
Modules over the token variables. Every user-facing string is a prop (the app supplies them from
`packages/app/src/i18n/en.json`); only stories contain English copy.

| Component | Built on | Notes |
|---|---|---|
| Button | native `<button>` (+ Radix `Slot` for `asChild`) | primary / secondary / ghost / danger, min 32 px tall |
| IconButton | Button | `label` prop is required → `aria-label`; 32 px (24 px small) |
| Slider | Radix Slider | unipolar, `aria-valuetext` via a formatter prop |
| VibeSlider | Radix Slider | **bipolar −1…1**, fill drawn from the centre, end labels as props, centre detent on pointer input, keyboard steps land exactly on 0, a reset-to-centre key, required `getValueText` (Simple mode shows no numbers, 11 §5) |
| Popover, Menu, Dialog, Tabs, Tooltip, Toast | Radix | thin styled wrappers keeping Radix's keyboard and focus behaviour |
| CommandPalette | Radix Dialog + own ARIA combobox/listbox | no `cmdk`: the combobox is ~150 lines and keeps the dependency count down |
| Chip | `<span>` or `<button>` | optional role/section swatch; the text label always carries the meaning |

Motion respects `prefers-reduced-motion` **and** a `data-motion="reduced"` override on `<html>`
(the setting in 11 §9): transforms are dropped and transitions become cross-fades (11 §3).

### Fonts (Q8)

Proposal: **Geist** (UI, variable, `wght` 100–900) + **Geist Mono** (times, BPM, values), both
SIL OFL 1.1, self-hosted as `woff2` (latin + latin-ext) in `packages/design/fonts/` with the
licence file next to them. No remote font loading (strict CSP, 01 §10). Recorded in 15 as
*proposed, pending owner sign-off*; swapping is a token change plus a file swap.

### Workshop: Storybook, not Ladle

Ladle 5.1.1 (latest) depends on Vite `^6` and would pull a second, older Vite into a repo on Vite 8.
Storybook 10.6 (`@storybook/react-vite`) declares Vite `^5 … ^8` and React `^19`, so it is the one
that fits the stack. It is a dev-only tool named by the WP itself.

### axe on all stories (acceptance 3)

`storybook build` to a static directory, then a Playwright (Chromium) script serves it, reads
`index.json`, opens every story **in both themes**, runs `@axe-core/playwright` with the WCAG 2.0–2.2
A/AA tags, and fails on any serious or critical violation. Overlay components have stories
rendered open so their content is actually scanned. It runs in `pnpm verify` via the package's
`test` script (it takes well under a minute); `pnpm --filter @bragi/design test:stories` runs it alone.

## Spec gaps found

- 11 §3 calls section hues "always shown with text labels", so section labels sit on the fills:
  the label colour per theme is part of the tokens and its contrast against every fill is checked.
- 02 `SectionKind` has 13 kinds; 11 §3 names hues for 7. The others get hues from the same family
  (pre-chorus/post-chorus lean towards chorus, build towards drop, solo/interlude neutral-ish,
  custom neutral), recorded in 11 §3.
- 02 `StemRole` has `other`, 11 §3 has "Synth / Other": one token, `synth`, aliased by `other`.
- No pattern or contrast rule exists for the energy gradient: treated as an essential graphic
  (3:1 against the canvas background at every stop).

## Where the plan changed

- **The dark role colours are not the 11 §3 hexes verbatim.** They were re-derived in OKLCH so that
  every pair stays above its ΔE00 budget under all four visions (amber vs gold under deuteranopia
  was the binding case: 4.7 with the published values). 11 §3 now carries the final values for both
  themes.
- **Sections are six families, not thirteen hues.** Thirteen hues cannot stay distinguishable at any
  meaningful ΔE00, so `SectionKind` maps onto neutral / blue / warm / purple / red-orange / teal
  (`src/tokens/mapping.ts`), and 11 §3 lists the mapping.
- **The energy gradient is deep, not bright, in the light theme.** Checking every stop at 3:1 against
  the canvas is only possible there with a dark ramp (`#3054AE → #B51C79`). Recorded in 11 §3.
- **Distinguishability budgets are per vision** (`tokens.json → distinguishability`). One number for
  all four would have been either trivially loose on unmodified vision or impossible under
  protanopia: roles 14 normal / 4 simulated, sections 12 / 5, adjacent energy stops 24 / 6.
- **The scrim's decorative bar is 1.02, not 1.2.** On the dark canvas the largest ratio any scrim can
  reach is 1.04, so the check asserts what is physically available ("a scrim darkens, never lightens")
  and the reason is in `tokens.json`.
- **`culori` and `@types/culori` were dropped.** `src/tokens/oklch.ts` implements OKLCH ↔ sRGB in
  ~40 lines and is covered by tests against the published OKLCH value for sRGB red, so the dependency
  the WIP added was not needed. The throwaway palette solver was deleted after use.
- **The focus ring is checked against surfaces, not against controls.** It is drawn with
  `outline-offset`, so the ring meets the canvas/surface behind a button; no single ring colour could
  otherwise clear 3:1 against both the dark canvas and a mid-tone accent fill.
- **`Menu` gained a `modal` prop.** A modal Radix menu paints `aria-hidden` over the page behind it,
  including its own trigger, which axe's `aria-hidden-focus` rule flags even though Radix also traps
  focus. The default stays modal (Radix's behaviour, covered by the interaction tests); the story that
  renders a menu open uses `modal={false}` and a disabled trigger, and the difference is documented in
  `Menu.stories.tsx`.
- **`CommandPalette` needed three ARIA fixes** that only the axe pass could find: the group wrapper is
  a `<fieldset>/<legend>` (a `div role="group"` is not the semantic element), options carry
  `tabIndex={-1}` (focus never leaves the input; `aria-activedescendant` points at them), and the
  listbox renders only while something matches — an empty listbox containing a "no matches" paragraph
  violates `aria-required-children`. An empty input also kept a dangling `aria-controls`.
- **The axe script disables transitions before each scan.** Without it, `data-theme` switches and
  Radix's entry animations are sampled mid-flight and axe reports contrast ratios that no user ever
  sees (it reported 16 such violations on the first run).
- **The scaffold test was fixed.** `src/__tests__/index.test.ts` used `new URL(..., import.meta.url)`,
  which is not a `file:` URL under Vitest's web transform mode (the mode `jsdom` selects), so it
  failed as soon as this package had a Vitest config. It now uses `import.meta.dirname`.
- **`turbo.json`'s `test` inputs grew** (`**/*.css`, `tokens.json`, `snapshots/**`, `.storybook/**`).
  Without them a token change would not invalidate Turbo's cache for the test task, and a stale
  "green" result could be replayed over a changed palette.

## Verification notes

- `axe-stories.mjs` also prints what axe could not decide, so the gaps are visible rather than
  silent: `bypass` (the Storybook preview iframe has no skip link — a host-page rule, not a
  component), `aria-hidden-focus` on Radix's own focus-guard spans, six `color-contrast` and six
  `aria-valid-attr-value` items on portaled content whose background/idrefs axe cannot resolve. The
  colours involved are all declared pairings in `tokens.json`, so the contrast test covers them.
- Only Chromium is exercised. `playwright` needs `pnpm exec playwright install chromium` once per
  machine; the run reports 0 scans and fails loudly if the browser or `storybook-static` is missing.

## Deferrals

- **`SectionKind` / `StemRole` are redeclared** in `src/tokens/mapping.ts` because WP-0.2 has not
  generated `@bragi/schemas` yet. When it has, they become `import type { … } from "@bragi/schemas"`
  and the two tables stay.
- **Role patterns are data, not pixels.** `tokens.json.rolePatterns` names the nine paper textures
  and a test keeps the ids unique, but the textures are drawn by the canvas renderer (WP-1.9). DOM
  chips carry the role name instead of a pattern.
- **`IconButton` with `asChild`** cannot carry `loading`/`disabled` (a Slot cannot disable its child);
  the app must handle those on the child element.
- **`VibeSlider`'s PageUp/PageDown jump** is Radix's fixed 10 × step, not a token.
- The **`tokens.css` Biome exclusion** the plan mentioned was not needed: Biome leaves the generated
  file alone, and the byte-for-byte test keeps it honest anyway.
- **The font is a proposal** until the owner answers Q8. Swapping is a token change plus a file swap,
  as designed.
