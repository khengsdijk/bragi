# WP-1.11 — Export v1

- **Spec refs:** [03 §9](../../specs/03-audio-engine.md), [03 §2–§3](../../specs/03-audio-engine.md)
  (rayon, host split), [13](../../specs/13-agent-guide.md)
- **Depends on:** 1.1 (Done)
- **Size:** S
- **Branch:** `wp/1.11-export-v1`

## Goal

Turn the engine's offline `f32` render into files: WAV (16/24/32-bit float) and FLAC (16/24-bit)
mixdowns, and one file per track ("stems"), through `EngineHost.render` on both hosts.

**Acceptance (from [12](../../specs/12-roadmap.md) WP-1.11):** WAV/FLAC mixdown and stems export;
the exported mixdown of an unedited project nulls against the working asset <= -60 dBFS.

## Approach

### Where the code lives

| Piece | Home | Why |
|---|---|---|
| Encoders (WAV, FLAC), dither, naming, metadata, mixdown and stem orchestration | new `bragi_engine::export` module | Platform-free, so the **same bytes** come out of WASM and native, and it compiles for `wasm32-unknown-unknown` (13 §3) |
| Per-track parallelism | `rayon`, behind a `parallel` cargo feature on `bragi-engine`, enabled only by `bragi-engine-native` | 03 §3 puts the rayon pool in the native crate; wasm32 has no threads, so the wasm build runs the same code sequentially |
| `export` entry on the service / wasm instance | `bragi-engine-native::service`, `bragi-engine-wasm` | Glue only |
| `EngineHost.render` returns encoded files | `packages/platform` types + both adapters | The TS surface already has `RenderJob` and `RenderResult`; `RenderResult` gains `files` |

### Formats

- **WAV**: RIFF, PCM 16/24 little-endian integer or IEEE float 32 (`format 3`), `LIST/INFO` chunk
  for metadata. Mixdown at 48 kHz stereo (02 §2.2).
- **FLAC**: native-frame encoder written in this repo (STREAMINFO with MD5, VORBIS_COMMENT,
  fixed predictors order 0-4 with the best chosen per frame, partitioned Rice residuals, a
  verbatim fallback, CRC-8 and CRC-16). 16 and 24 bit, 4096-sample blocks. Verified by decoding
  with symphonia (already a dependency) in the tests.
- **MP3 and `normalize`** are out of this WP: MP3 needs an encoder decision (03 §9 defers it to
  "the export work package", but the roadmap's acceptance names WAV/FLAC only); `normalize` needs
  BS.1770 loudness which the engine does not have yet (Q26). Both are rejected with a typed
  error and recorded in 15.

### Determinism and dither

Float -> integer conversion rounds to nearest at `2^(bits-1)`, clamps, and **adds no dither unless a
seed is supplied** (03 §9). With a seed, TPDF dither (xorshift64*) is added for 16 and 24 bit. 32-bit
float output is never dithered.

### Stems

Each track is rendered alone: the plan is cloned with only that track, with mute/solo cleared (a
stem is the track as written, not as auditioned), master gain and automation kept (so the stem sits
at mixdown level) and the **safety limiter bypassed** (it is non-linear, so stems summed equal the
mixdown exactly whenever the mixdown limiter is not engaged). Tracks render in parallel under
`parallel` and are collected in document order.

### Naming and metadata

- Mixdown: `<title>.<ext>`. Stems: `<NN>-<track name>.<ext>` (NN = 1-based document index, 2
  digits), names sanitised to `[A-Za-z0-9 _-]` and trimmed; collisions are impossible because of NN.
- Metadata (WAV INFO / FLAC Vorbis comments): title, track name for stems, software
  (`Bragi <version>`), comment with BPM and key when known, creation date when the caller supplies
  it. The engine never reads the clock.

### Host surface

`RenderJob.mixdown|stems` now produce encoded files. `RenderResult` becomes
`{ channels, sampleRate, format, frames, files: { name, bytes }[] }`. `context` and `cache` kinds
remain rejected in v1 (generation conditioning belongs to the generation WPs).

- Web: the engine worker calls the wasm `export(job_json)`.
- Desktop: `engine_render` runs `EngineService::export`, rayon-parallel.

## Outcome (written after implementation)

**What landed**

| Area | Where |
|---|---|
| WAV encoder (16/24 int, 32 float, `fact` + `LIST/INFO`) | `crates/bragi-engine/src/export/wav.rs` |
| FLAC encoder (STREAMINFO + MD5, Vorbis comment, fixed predictors 0-4, partitioned Rice, 4 stereo modes, variable-blocksize tail) | `.../export/flac.rs`, `md5.rs` |
| TPDF dither with a seed, round-to-nearest otherwise | `.../export/quantize.rs` |
| Mixdown, stems, naming, metadata, job JSON parser, export frame | `.../export/mod.rs` |
| Native service `export`, Tauri `engine_render` (raw binary reply), `bragi-render --export-job` | `crates/bragi-engine-native`, `apps/desktop/src-tauri/src/engine.rs` |
| WASM `export_frame` | `crates/bragi-engine-wasm/src/lib.rs` |
| `RenderResult.files`, `ExportMeta`, `decodeExportFrame`; web worker transfers per-file buffers | `packages/platform/src/**` |
| Native-vs-WASM export parity | `scripts/conformance.mjs` |

**Acceptance: the exported mixdown of an unedited project nulls against the working asset <= -60 dBFS**

`crates/bragi-engine/tests/export.rs::unedited_mixdown_nulls_against_the_working_asset`. The
fixture is generated at test time (two tones plus seeded noise, peak 0.6 FS, 3 s) and encoded to
24-bit FLAC; decoding it back is the "working asset" (the same shape ingest produces, 04 §3.1). An
unedited one-clip project is exported and the exported bytes are decoded by **symphonia** (an
independent implementation) and nulled sample-by-sample against the working asset:

| Export | Null vs working asset |
|---|---|
| WAV 24-bit | -inf dBFS (bit exact) |
| FLAC 24-bit | -inf dBFS (bit exact) |
| WAV 16-bit (no dither) | -101.1 dBFS |
| FLAC 16-bit (no dither) | -101.1 dBFS |
| WAV 32-bit float | -inf dBFS |

All are far under the -60 dBFS criterion; the 16-bit figure is the quantisation floor. The test also
asserts per-format ceilings (-130 dBFS for 24-bit, -85 dBFS for 16-bit).

**Other proofs**

- FLAC round trip is bit exact through symphonia at 16 and 24 bit for lengths
  0/1/3/5/255/256/257/4095/4096/4097/9000, full-scale square + silence, and mono; STREAMINFO MD5
  equals an independent MD5 of the audio (MD5 itself is checked against the RFC 1321 vectors; CRC-8/16
  against the standard check values).
- Stems: named `01-<track>.wav`..., ordered, muted tracks still exported, summed stems null against the
  all-unmuted mixdown at -inf dBFS, parallel stems byte-equal a sequential render, unknown track IDs are
  rejected.
- Determinism: the same job twice gives identical bytes; dither is off without a seed and reproducible
  with one.
- Native-vs-WASM (`pnpm test:conformance`): WAV exports of the gated fixtures null at **-174.6 to
  -185.0 dBFS** (gate: <= -90); FLAC exports are reported byte-identical or not (the render differs in
  the last float bits, which can cross a rounding boundary, so bytes are not guaranteed equal).
- FLAC size: 219 243 bytes vs 288 076 bytes WAV for one second of noisy tonal 24-bit stereo.
- Gates: `cargo clippy --workspace --all-targets -D warnings`, `cargo test --workspace`, the wasm32
  build of `bragi-engine`/`bragi-engine-wasm`, Biome, `tsc` and Vitest (97 tests in `@bragi/platform`),
  all inside `pnpm verify`.

**Dependencies**

| Dependency | Licence | Note |
|---|---|---|
| `rayon` 1.12 | MIT OR Apache-2.0 | Optional in `bragi-engine` (`parallel` feature), enabled only by `bragi-engine-native`; wasm32 never links it. Named in 03 §2/§3 and 12, so no ADR. |
| FLAC encoder, WAV writer, MD5, dither | in-repo | No FLAC/WAV crate: ~500 lines whose correctness is proven by an independent decoder, and no licence or wasm risk. No ADR needed (no new dependency). |

**Deferred (and why)**

- MP3 and `normalize` (needs BS.1770 loudness + true-peak, Q26): Q37. Both are rejected with a typed error.
- `context` and `cache` render kinds (generation WPs).
- Export progress, cancellation and not blocking the desktop service mutex: Q39.
- Export bundle ("Open in your DAW"): WP-6.6.
- A save dialog / file write: the host returns bytes and names; the UI WP decides where they go.
- The safety limiter versus the null criterion for loud assets: Q38.

**Deviations from the spec / plan, recorded**

- `RenderResult.bytes` became `files[]` (stems need several files). The one-file mixdown is
  `files[0]`.
- `RenderJob` gained optional `meta`, `ditherSeed` (and `startSample`/`frames` for stems).
- The Tauri `engine_render` reply is a raw binary export frame rather than JSON.
- The 1.1 raw-`f32` `EngineService::render` stays for tests and the conformance harness.
- Web `AudioFormat` for `context`/`cache` jobs no longer fabricates a 32-bit WAV result: those kinds
  now fail with a typed error.
- A stream whose last block would be under 16 samples is written as variable-blocksize FLAC
  (otherwise symphonia and some decoders reject it). A mixdown of fewer than 16 frames is still valid
  FLAC but symphonia refuses to decode it; irrelevant for real exports.
