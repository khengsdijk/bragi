# WP-1.11 — Export v1

- **Spec refs:** [03 §9](../../specs/03-audio-engine.md), [03 §2–§3](../../specs/03-audio-engine.md)
  (rayon, host split), [13](../../specs/13-agent-guide.md)
- **Depends on:** 1.1 (Done)
- **Size:** S
- **Branch:** `wp/1.11-export-v1`

## Goal

Turn the engine's offline `f32` render into files: WAV (16/24/32-bit float) and FLAC (16/24-bit)
mixdowns, and one file per track ("stems"), through `EngineHost.render` on both hosts.

**Acceptance (from [12](../../specs/12-roadmap.md) WP-1.11):** WAV/FLAC mixdown and stems export;
the exported mixdown of an unedited project nulls against the working asset <= -60 dBFS.

## Approach

### Where the code lives

| Piece | Home | Why |
|---|---|---|
| Encoders (WAV, FLAC), dither, naming, metadata, mixdown and stem orchestration | new `bragi_engine::export` module | Platform-free, so the **same bytes** come out of WASM and native, and it compiles for `wasm32-unknown-unknown` (13 §3) |
| Per-track parallelism | `rayon`, behind a `parallel` cargo feature on `bragi-engine`, enabled only by `bragi-engine-native` | 03 §3 puts the rayon pool in the native crate; wasm32 has no threads, so the wasm build runs the same code sequentially |
| `export` entry on the service / wasm instance | `bragi-engine-native::service`, `bragi-engine-wasm` | Glue only |
| `EngineHost.render` returns encoded files | `packages/platform` types + both adapters | The TS surface already has `RenderJob` and `RenderResult`; `RenderResult` gains `files` |

### Formats

- **WAV**: RIFF, PCM 16/24 little-endian integer or IEEE float 32 (`format 3`), `LIST/INFO` chunk
  for metadata. Mixdown at 48 kHz stereo (02 §2.2).
- **FLAC**: native-frame encoder written in this repo (STREAMINFO with MD5, VORBIS_COMMENT,
  fixed predictors order 0-4 with the best chosen per frame, partitioned Rice residuals, a
  verbatim fallback, CRC-8 and CRC-16). 16 and 24 bit, 4096-sample blocks. Verified by decoding
  with symphonia (already a dependency) in the tests.
- **MP3 and `normalize`** are out of this WP: MP3 needs an encoder decision (03 §9 defers it to
  "the export work package", but the roadmap's acceptance names WAV/FLAC only); `normalize` needs
  BS.1770 loudness which the engine does not have yet (Q26). Both are rejected with a typed
  error and recorded in 15.

### Determinism and dither

Float -> integer conversion rounds to nearest at `2^(bits-1)`, clamps, and **adds no dither unless a
seed is supplied** (03 §9). With a seed, TPDF dither (xorshift64*) is added for 16 and 24 bit. 32-bit
float output is never dithered.

### Stems

Each track is rendered alone: the plan is cloned with only that track, with mute/solo cleared (a
stem is the track as written, not as auditioned), master gain and automation kept (so the stem sits
at mixdown level) and the **safety limiter bypassed** (it is non-linear, so stems summed equal the
mixdown exactly whenever the mixdown limiter is not engaged). Tracks render in parallel under
`parallel` and are collected in document order.

### Naming and metadata

- Mixdown: `<title>.<ext>`. Stems: `<NN>-<track name>.<ext>` (NN = 1-based document index, 2
  digits), names sanitised to `[A-Za-z0-9 _-]` and trimmed; collisions are impossible because of NN.
- Metadata (WAV INFO / FLAC Vorbis comments): title, track name for stems, software
  (`Bragi <version>`), comment with BPM and key when known, creation date when the caller supplies
  it. The engine never reads the clock.

### Host surface

`RenderJob.mixdown|stems` now produce encoded files. `RenderResult` becomes
`{ channels, sampleRate, format, frames, files: { name, bytes }[] }`. `context` and `cache` kinds
remain rejected in v1 (generation conditioning belongs to the generation WPs).

- Web: the engine worker calls the wasm `export(job_json)`.
- Desktop: `engine_render` runs `EngineService::export`, rayon-parallel.

### Dependencies

| Crate | Licence | Where | Note |
|---|---|---|---|
| `rayon` 1.12 | MIT OR Apache-2.0 | `bragi-engine` (optional) -> native only | Already named in 03 §2/§3 and 12; not a new framework, so no ADR. Already in the registry cache (transitive of other crates) |
| FLAC / WAV / MD5 | none | written in-repo | Avoids a dependency for ~400 lines whose correctness is proven by the symphonia round trip and RFC 1321 test vectors |

### Test plan

| Criterion | Proof |
|---|---|
| Null test <= -60 dBFS | `crates/bragi-engine/tests/export.rs`: generate a 24-bit working asset (FLAC, tone + noise, generated at test time), load an unedited one-clip project over it, export mixdown as 24-bit WAV, 24-bit FLAC and 16-bit WAV, **decode the exported bytes with symphonia** and null against the decoded working asset |
| WAV/FLAC correctness | unit tests: header fields, FLAC round trip bit-exact through symphonia at 16 and 24 bit, mono and stereo, silence, full-scale, odd lengths, MD5 vectors, CRC vectors |
| Stems | stems sum to the mixdown (<= -120 dBFS) when no limiting; names; mute/solo ignored; parallel == sequential bytes |
| Determinism | same job twice gives identical bytes; dither off without seed; seeded dither reproducible |
| Hosts | platform Vitest for both adapters (fake bridges); Rust service test; wasm export is covered by `pnpm test:conformance` extended with an export parity check (native bytes == wasm bytes) |
