# WP-0.1 — Monorepo scaffold & CI

- **Spec refs:** [01 §4](../../specs/01-architecture.md), [13](../../specs/13-agent-guide.md)
- **Depends on:** none
- **Size:** S
- **Branch:** `wp/0.1-monorepo-scaffold`

## Goal

Stand up the repository skeleton from [01 §4](../../specs/01-architecture.md) with working
per-language tooling, local infrastructure and CI, so every later work package has a place to
put its code and a gate that proves it still builds.

**Acceptance (from [12](../../specs/12-roadmap.md)):**
1. `pnpm i && pnpm build && pnpm test` succeeds on Ubuntu, macOS and Windows in CI.
2. `docker compose up` brings all infra services to healthy.

## Approach

Four toolchains, one repo, no cross-language build coupling:

| Layer | Root | Tools |
|---|---|---|
| TypeScript | `/` | pnpm workspaces + Turborepo, Biome, TypeScript project references, Vitest |
| Rust | `/Cargo.toml` | Cargo workspace, rustfmt, clippy (`-D warnings`), workspace lints |
| Python | `/services/workers` | uv workspace, ruff, mypy, pytest |
| Infra | `/infra` | docker compose: Postgres 17 + pgvector, MinIO, NATS JetStream, Mailpit |

Turborepo orchestrates only the TS graph. Rust and Python are driven by root `package.json`
scripts grouped by verb (`lint:rust`, `test:py`, `build:wasm`, …), with `pnpm verify` running the
whole gate, so one command set works for humans and agents.

### Scaffold depth per directory

Every directory in [01 §4](../../specs/01-architecture.md) exists and carries a `README.md`
stating what it is and which WP fills it. Beyond that:

- **Real but minimal TS packages** (`package.json`, `tsconfig.json`, `src/index.ts`,
  one smoke test): `packages/{app,design,render-canvas,render-universe,platform,schemas,api-client}`
  and `services/api`. The source exports nothing but a package identity constant; its purpose is
  to prove the lint → typecheck → build → test chain really runs on every OS.
- **Real but minimal crates** (`Cargo.toml`, `src/lib.rs` with one tested function):
  `crates/{bragi-model,bragi-dsp,bragi-engine,bragi-engine-wasm,bragi-engine-native}`.
- **Real but minimal Python packages** (`pyproject.toml`, package dir, one test):
  `services/workers/{bragi_common,analysis,embed,generate}`.
- **README-only placeholders:** `apps/web`, `apps/desktop`, `packages/model-wasm`,
  `infra/deploy`, `fixtures/*`. These are filled by WP-0.5 (apps), WP-0.3 (model-wasm) and
  Phase 1+ (fixtures), and scaffolding them now would mean implementing those WPs early.

## Test plan

| Acceptance criterion | How it is proven |
|---|---|
| `pnpm i && pnpm build && pnpm test` on 3 OSes | `ci.yml` job `ts` with an OS matrix runs exactly that sequence |
| Rust toolchain honest | `ci.yml` job `rust` (3 OSes): `cargo fmt --check`, `cargo clippy -D warnings`, `cargo test`, plus a `wasm32-unknown-unknown` build of the wasm-targeting crates |
| Python toolchain honest | `ci.yml` job `python`: `uv sync`, `ruff check`, `ruff format --check`, `mypy`, `pytest` |
| `docker compose up` → all healthy | `pnpm infra:up` (`up -d --wait --wait-timeout 180`) plus assertions that each service does what 01 §1 and 05 §4–§6 need of it |
| Repo layout matches 01 §4 | `scripts/check-layout.mjs`, run by `pnpm lint:layout`: it **parses the tree in 01 §4** and requires every directory in it to exist with a README |

The layout check is the one piece of real logic in this WP, so it is written test-first
(Vitest, `scripts/__tests__/check-layout.test.mjs`). It derives its list from the spec rather than
restating it, so adding a directory to the 01 §4 tree makes `pnpm lint:layout` fail until the
directory exists. Four directories required by other specs (`docs` from 13 §2, the `fixtures/*`
subdirectories from 13 §6) are listed explicitly as `EXTRA_DIRS`.

## Decisions / spec notes

- **Branch, not worktree.** AGENTS.md §2 prescribes a `wp/<id>-<slug>` branch; this repo had no
  git history at all before this WP, so `main` holds the specs and this branch holds the scaffold.
- **Python 3.12 is a pin, not a local fact.** The spec requires 3.12 and this machine has 3.11 on
  `PATH`; `requires-python = ">=3.12"` plus `.python-version` makes uv fetch and use 3.12, so the
  system interpreter is never used.
- **No `packages/model-wasm` workspace member yet.** It is *generated* output (01 §4, 13 §3), so
  WP-0.3 creates it. A README placeholder marks the slot.
- **No new major dependencies.** Everything added here is tooling named in
  [ADR-0001](../../specs/decisions/ADR-0001-tech-stack.md) / [01 §1](../../specs/01-architecture.md),
  so no new ADR is required.

## Review outcome

A fresh-context agent reviewed the whole branch against the specs. Fixed in the branch:

| Finding | Fix |
|---|---|
| `astral-sh/setup-uv@v10` is not a resolvable ref, and `python-version-file` is not one of its inputs — the Python job could never start | Pinned `@v10.3.0`, switched to `python-version: "3.12"` (verified against the action's `action.yml` and the GitHub refs API) |
| 12 §8 and the README claimed a green three-OS CI matrix that had never run | Hosted CI dropped (owner's decision); the status rows now say what was verified and on which machine, and the cross-platform gap is [Q11](../../specs/15-open-questions.md) |
| `pg_isready` without `-h` answers over the Unix socket, where the entrypoint's temporary init server also listens — the service could report healthy before `postgres/init/*.sql` had run | Healthcheck forces TCP |
| `up --wait` has no timeout, and `restart: unless-stopped` means a crash-looping container is retried rather than failing fast | `--wait-timeout 180` in `infra:up` and in the workflow, plus `timeout-minutes` per job |
| Workflow-level `RUSTFLAGS: -D warnings` made CI stricter than every local command, including for the generated code landing in `bragi-model` in WP-0.2 | Removed; clippy already denies warnings on its own command line |
| The layout guard restated 01 §4 by hand, and its test asserted 23 of 34 entries | Guard derives from the spec; the test parses the tree and checks the derived list, verified by adding a directory to a copy of the spec |
| `[profile.dev.package."*"] opt-level = 2` does not apply to workspace members, so it was a no-op with a comment claiming otherwise | Replaced with a note for WP-1.1, which owns the conformance tests that need it |
| ``[`specs/…`]`` is intra-doc-link syntax: 10 rustdoc warnings from `cargo doc` | Plain code spans; `cargo doc --workspace` is now warning-free |
| `tsconfig.base.json` was in neither turbo's task nor global hash, so editing compiler options left `dist/` stale behind a FULL TURBO | `globalDependencies: ["tsconfig.base.json"]` |
| `tsconfig.test.json` claimed to typecheck `scripts/**` but `allowJs` was off, so the only real logic in the WP was excluded | `allowJs` + `checkJs` on; the JSDoc was already written for it |
| `Cargo.toml` `repository` pointed at a URL that 404s | Corrected to the real remote |

Deferred, with reasons:

- **Assert MinIO state via `mc --json` + `jq`, and pin the image digest.** The CI assertions match on
  human-readable `mc` output, and the image floats on `:latest`. Both only matter for the dormant
  workflow; the digest in the compose comment could not be confirmed multi-arch from this machine
  (`docker manifest inspect` and `buildx imagetools` are both denied anonymously for `minio/minio`).
- **Pass `--env-file infra/.env` explicitly.** Compose would fail outright when the file is absent,
  and it is gitignored and optional — every variable has a default.
- **A `py:sync` script.** `uv sync` runs automatically as part of `uv run`, which is what
  `lint:py` and `test:py` use.
