# WP-0.1 — Monorepo scaffold & CI

- **Spec refs:** [01 §4](../../specs/01-architecture.md), [13](../../specs/13-agent-guide.md)
- **Depends on:** none
- **Size:** S
- **Branch:** `wp/0.1-monorepo-scaffold`

## Goal

Stand up the repository skeleton from [01 §4](../../specs/01-architecture.md) with working
per-language tooling, local infrastructure and CI, so every later work package has a place to
put its code and a gate that proves it still builds.

**Acceptance (from [12](../../specs/12-roadmap.md)):**
1. `pnpm i && pnpm build && pnpm test` succeeds on Ubuntu, macOS and Windows in CI.
2. `docker compose up` brings all infra services to healthy.

## Approach

Four toolchains, one repo, no cross-language build coupling:

| Layer | Root | Tools |
|---|---|---|
| TypeScript | `/` | pnpm workspaces + Turborepo, Biome, TypeScript project references, Vitest |
| Rust | `/Cargo.toml` | Cargo workspace, rustfmt, clippy (`-D warnings`), workspace lints |
| Python | `/services/workers` | uv workspace, ruff, mypy, pytest |
| Infra | `/infra` | docker compose: Postgres 17 + pgvector, MinIO, NATS JetStream, Mailpit |

Turborepo orchestrates only the TS graph. Rust and Python are driven by root `package.json`
scripts (`rust:*`, `py:*`) so that one command set works for humans, agents and CI.

### Scaffold depth per directory

Every directory in [01 §4](../../specs/01-architecture.md) exists and carries a `README.md`
stating what it is and which WP fills it. Beyond that:

- **Real but minimal TS packages** (`package.json`, `tsconfig.json`, `src/index.ts`,
  one smoke test): `packages/{app,design,render-canvas,render-universe,platform,schemas,api-client}`
  and `services/api`. The source exports nothing but a package identity constant; its purpose is
  to prove the lint → typecheck → build → test chain really runs on every OS.
- **Real but minimal crates** (`Cargo.toml`, `src/lib.rs` with one tested function):
  `crates/{bragi-model,bragi-dsp,bragi-engine,bragi-engine-wasm,bragi-engine-native}`.
- **Real but minimal Python packages** (`pyproject.toml`, package dir, one test):
  `services/workers/{bragi_common,analysis,embed,generate}`.
- **README-only placeholders:** `apps/web`, `apps/desktop`, `packages/model-wasm`,
  `infra/deploy`, `fixtures/*`. These are filled by WP-0.5 (apps), WP-0.3 (model-wasm) and
  Phase 1+ (fixtures), and scaffolding them now would mean implementing those WPs early.

## Test plan

| Acceptance criterion | How it is proven |
|---|---|
| `pnpm i && pnpm build && pnpm test` on 3 OSes | `ci.yml` job `ts` with an OS matrix runs exactly that sequence |
| Rust toolchain honest | `ci.yml` job `rust` (3 OSes): `cargo fmt --check`, `cargo clippy -D warnings`, `cargo test`, plus a `wasm32-unknown-unknown` build of the wasm-targeting crates |
| Python toolchain honest | `ci.yml` job `python`: `uv sync`, `ruff check`, `ruff format --check`, `mypy`, `pytest` |
| `docker compose up` → all healthy | `ci.yml` job `infra` runs `docker compose up -d --wait`, then prints `docker compose ps`; verified locally too |
| Repo layout matches 01 §4 | `scripts/check-layout.mjs`, run by `pnpm lint:layout` in the `ts` job: every path in 01 §4 exists and has a README |

The layout check is the one piece of real logic in this WP, so it is written test-first
(Vitest, `scripts/__tests__/check-layout.test.mjs`).

## Decisions / spec notes

- **Branch, not worktree.** AGENTS.md §2 prescribes a `wp/<id>-<slug>` branch; this repo had no
  git history at all before this WP, so `main` holds the specs and this branch holds the scaffold.
- **Python 3.12 is a pin, not a local fact.** The spec requires 3.12 and this machine has 3.11 on
  `PATH`; `requires-python = ">=3.12"` plus `.python-version` makes uv fetch and use 3.12, so the
  system interpreter is never used.
- **No `packages/model-wasm` workspace member yet.** It is *generated* output (01 §4, 13 §3), so
  WP-0.3 creates it. A README placeholder marks the slot.
- **No new major dependencies.** Everything added here is tooling named in
  [ADR-0001](../../specs/decisions/ADR-0001-tech-stack.md) / [01 §1](../../specs/01-architecture.md),
  so no new ADR is required.
