# WP-1.9 — Song Canvas renderer v1 (view + playback)

- **Spec refs:** [07 §1, §2, §5, §8, §9](../../specs/07-song-canvas.md) (whole file for context),
  [11 §2, §3, §6.1](../../specs/11-ux-and-accessibility.md), [02](../../specs/02-song-model.md),
  [01 §4](../../specs/01-architecture.md), [03 §3, §5](../../specs/03-audio-engine.md)
- **Depends on:** 0.5, 0.6, 1.1 (Done), 0.3 and 1.8 (Done)
- **Size:** L
- **Branch:** `wp/1.9-song-canvas-renderer`

## Goal

Open a song and see it: skyline, section blocks, harmony strip, ribbons, beat grid, playhead,
zoom/pan across the L2 levels, a selection model, solo/mute from the ribbons, progressive states with
shimmer, the accessible DOM grid, and a transport bar wired to `EngineHost`. WP-1.10 builds the
upload-to-live-analysis flow on this canvas, so the renderer's **data-in API stays small**:
a view-model document plus an analysis-progress object in, typed events out.

**Acceptance (from [12](../../specs/12-roadmap.md)):**
1. [07 §9](../../specs/07-song-canvas.md) budgets are met (60 fps, 10-minute song with 12 ribbons,
   <= 8 ms render, first canvas < 500 ms).
2. WebGL2 fallback visual snapshots match (Playwright, WebGPU on and off, 13 §6).
3. Accessible grid content matches the document (automated test).
4. DoD: axe has no serious/critical issues, keyboard reachable, `pnpm verify` green.

## Dependencies (13 §1 rule 6)

PixiJS v8 and Zustand are **already approved** in the stack table of [01 §1](../../specs/01-architecture.md)
and [ADR-0001](../../specs/decisions/ADR-0001-tech-stack.md); no ADR is needed. Both are MIT.
`jsdom` and `@testing-library/*` are already used by `packages/design` (test-only).

## Starting point found in the repo

- `render-canvas`, the song feature and `model-wasm` consumers are empty; there is no Song Store.
- The web `EngineHost` is a tested **protocol** (`createWasmEngineHost`) but its browser wiring was
  never run (1.1 "Deferred"). Reading it, four things cannot work in a browser as written: the
  worklet uses dynamic `import()` and `fetch` (neither exists in `AudioWorkletGlobalScope`), the
  wasm-bindgen glue needs `TextDecoder` (absent there), the command ring is posted but never consumed,
  and the state block is *transferred* (detached) rather than shared. Making these work is in scope,
  because the transport bar is meaningless without them. They are fixed in `packages/platform`.
- `EngineHost.applyDelta` on the web has no worklet implementation. Mute/solo deltas are applied to
  the host's copy of the document (`tracks_updated` carries whole tracks) and the plan is recompiled
  with `load_project`; the Rust engine is unchanged.

## Approach

### `packages/render-canvas` (framework-agnostic, no React)

Pure modules (Vitest in Node), then a thin Pixi layer:

| Module | Responsibility |
|---|---|
| `types.ts` | Data-in: `CanvasDocument` (sections/tracks in seconds + ticks), `AnalysisView` (stage status, energy, chords, envelopes). Data-out: `CanvasEvents`. |
| `viewport.ts` | px/beat zoom, L2-far/L2/L2-near/L3 levels (07 §2.1), cursor-anchored zoom, pan clamp, fit-song. |
| `selection.ts` | The four-variant selection and its `?sel=` encoding (07 §5). |
| `geometry.ts` | Catmull-Rom skyline, envelope binning to ~1-2 bins/pixel (LOD), triangle-strip ribbon meshes, culling. |
| `layout.ts` | Lane rectangles and hit testing (sections, ribbons, mute/solo buttons). |
| `progressive.ts` | Which layers are live/pending per analysis stage (07 §8). |
| `palette.ts` | Reads `@bragi/design/tokens.json` (dark/light). |
| `song-canvas.ts` | `SongCanvas`: Pixi `Application` (`preference: webgpu`, WebGL2 fallback), layer containers in 07 §9 z-order, ticker, `setDocument/setAnalysis/setPlayhead/setSelection/setViewport`, `on(event)`, `destroy()`. |

Solo/mute leave the canvas only as events (`trackToggle`); `packages/app` turns them into `track.update`
op batches. The renderer never touches the document.

### `packages/app/src/features/song/`

- `state/song-store.ts`: **the Song Store**, a Zustand vanilla store around `@bragi/model-wasm`
  (`loadProject` / `applyBatch` / `diffDocs`). The only place a document changes.
- `api/view-model.ts`: document JSON -> `CanvasDocument` through the wasm tempo map
  (`sectionSpans`, `ticksToSeconds`), so tick/second conversion stays in `bragi-model`.
- `api/demo-song.ts` + `api/demo-audio.ts`: a generated demo song (no committed audio; stems are
  synthesised WAVs put in the blob cache by hash) and a deterministic synthetic `AnalysisView`.
- `components/`: `SongCanvasView` (mounts the class, bridges events), `AccessibleGrid` (ARIA grid,
  11 §6.1), `TransportBar`, `ZoomControls`, and the `/demo` route page.
- Strings in `i18n/en.json`; selection in the URL search param `sel`.

### `packages/platform` + `apps/web`

Worklet/engine wiring fixes above; `createEngineHost` in `auto.ts`; Vite emits the worklet and wasm.

## Test plan

| Layer | What |
|---|---|
| Vitest `render-canvas` | viewport math, level thresholds, selection round-trip, LOD binning, mesh geometry, hit testing, progressive states, palette. |
| Vitest `app` (jsdom) | Song Store ops/undo identity; view-model vs document; **accessible grid == document** (rows, columns, names, bars, energy words, playing cells, chords); i18n copy rules; transport wiring against a fake `EngineHost`. |
| Playwright (web) | demo route renders in Chromium/Firefox/WebKit; axe (serious/critical = 0) ; keyboard path; solo/mute commit one op batch; playback advances the playhead through the real worklet; **screenshots, WebGPU on vs off** (`toHaveScreenshot`); **performance run** with a 10-minute / 12-ribbon song. |

## Budgets to record (07 §9)

60 fps while playing and zooming; <= 8 ms render time per frame; first canvas < 500 ms; measured in
`apps/web/e2e/canvas.perf.spec.ts`, numbers go into the outcome below.

## Out of scope (stays in 07 / later WPs)

Tools other than select (lasso, paint, split, erase, explain), section drag/resize (07 §4.1-4.2),
audition bar, history panel, skyline editing, minimap/extend handle, lyrics lane, L3 spectrogram
toggle, command palette. Real analysis blobs arrive with WP-1.10; v1 takes them through `AnalysisView`.
