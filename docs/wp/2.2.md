# WP-2.2 — Section editing interactions

- **Spec refs:** [07 §4.1–4.2, §10](../../specs/07-song-canvas.md), [02 §5.1–5.2](../../specs/02-song-model.md), [03 §5.3](../../specs/03-audio-engine.md), [11 §6](../../specs/11-ux-and-accessibility.md), [01 §5](../../specs/01-architecture.md)
- **Depends on:** 2.1 (Done: history store, `startGesture`, `coalesceBatches`)
- **Size:** L
- **Branch:** `wp/2.2-section-editing`

## Goal

Rearrange a song by its sections: drag to reorder with live audio, Alt-drag to duplicate, delete,
resize by the right edge (trim / loop / stretch), split, smart transitions, a context menu, and a
keyboard path and command palette entry for every action.

**Acceptance (12):** 07 §10 check 1 (reordering Chorus 2 before Verse 2 updates audio while
dragging and commits a single `section.move` batch; undo restores the exact document) and check 6
(every action reachable by keyboard and the command palette). No clicks at new boundaries in renders
(automated discontinuity check).

## What exists

- The model has every op: `section.move` (absolute `toIndex`), `.duplicate`, `.remove`,
  `.resize` (`trim`/`loop`/`stretch`), `.split`, `.update` (label, kind, locked), `.set_transition`.
- WP-2.1 added the gesture layer: `startGesture` previews steps on a copy of the document
  (`SongState.preview`), sends their deltas to the engine, and commits once; consecutive
  `section.move`s of one section fold into the last.
- The engine **hard-cuts** at section windows: a clip is clamped at its section end with no fade,
  and `transitionIn` (`cut`/`crossfade`) is not rendered at all.
- There is no command palette, no context menu on sections, and the canvas has no drag handling for
  sections (selection only).

## Approach

### A. Engine: boundaries without clicks (`bragi-engine`, Rust)

Per section boundary B and track, the planner compares the outgoing and incoming material:

- **Contiguous** (same asset, and the source position the outgoing clip reaches at B equals where
  the incoming clip starts, within one sample): nothing changes. An unedited song renders exactly
  as today, so the export null tests stay valid.
- **Discontinuous, `transitionIn.kind == "cut"`:** a 5 ms equal-power crossfade centred on B
  (`BOUNDARY_FADE_MS`, the same order as the 03 loop-point fade). The outgoing clip keeps playing
  2.5 ms past B from its source *handle* (material after its window, when the asset has it) and
  fades out; the incoming clip starts 2.5 ms before B from its handle and fades in. Without a
  handle that side fades over its own half only.
- **`crossfade`:** the same with `transitionIn.lengthTicks` (converted at B's tempo), centred on B.
- **`generated`:** unchanged here (WP-2.7 renders the bridging asset); treated as `crossfade` of its
  length until then, with a plan warning.

Segments gain an optional pre-roll/post-roll in source samples and a boundary fade (separate from
the clip's own fades; gains multiply). Seeking into a crossfade region is sample-accurate. 02 §3.5 /
03 get one paragraph defining the centred crossfade and the contiguity rule.

Tests: unedited fixture renders bit-identical to before (the existing golden/null tests); a
generated fixture of low-frequency sines with a different phase per section, reordered so every
boundary is discontinuous, rendered offline: **no sample step at any boundary larger than −40
dBFS above the signal's own maximum step** (07 §10 check 4 metric) for `cut`; a `crossfade` of 1 beat
has an equal-power gain law (no dip > 1.5 dB for uncorrelated noise); conformance (WASM = native);
`no_alloc` unchanged.

### B. Actions, keyboard, context menu, command palette (TS)

- `packages/app/src/features/song/state/section-ops.ts`: batch builders with plain-language labels
  (11 §2): `moveSectionBatch(doc, id, toIndex, { smooth })`, `duplicateSectionBatch`,
  `removeSectionBatch(…, { smooth })`, `renameSectionBatch`, `setSectionKindBatch`,
  `lockSectionBatch`, `resizeSectionBatch(doc, id, bars, mode)`, `splitSectionBatch(doc, id, atTick)`
  (snapped to a bar). **Smart transitions** (02 §5.1): when on, a move also sets the moved
  section's and the section now following its old position's `transitionIn` to `crossfade` of one
  beat if they were `cut`; a remove smooths the section that now follows the gap. Unit tests apply
  each batch through the model and undo it (deep-equal).
- The setting `smartTransitions` (default on) lives in `local_settings` (LocalDB, WP-2.1) behind a
  small settings store, with a toggle in the context menu's footer or the song's settings — the
  agent picks the least intrusive existing place.
- **Command registry + palette** (`packages/app/src/features/commands/`): a registry of commands
  `{ id, label, shortcut?, enabled(ctx), run(ctx) }`; `Cmd/Ctrl+K` opens a searchable palette
  (accessible combobox + listbox, design-system components). Section commands: Move earlier/later,
  Duplicate, Remove, Rename…, Change type…, Lock from AI / Unlock, Loop this part, Make longer…,
  Make shorter…, Split at playhead, Undo, Redo, Version history (2.1). AI commands (Regenerate…,
  Explain, Continue with AI, Condense) are **not shown** until their WPs.
- **Keyboard** (11 §6.2): `Alt+←/→` moves the focused section, `Alt+Shift+←/→` shortens (trim) or
  lengthens (loop) by one bar, `Delete`/`Backspace` removes, plus the palette. Each commits one batch
  and announces it ("Chorus 2 moved after Verse 3").
- **Context menu** on a section (right-click on the canvas block, `Shift+F10`/context-menu key on
  the focused grid cell): the 07 §4.1 list without the AI items. "Make longer…/shorter…" open a small
  dialog (bars + mode) that commits `section.resize`.
- **Loop this part:** `EngineController.setLoop` gains a range (`{ startSec, endSec } | null`); the
  transport loop button keeps looping the whole song.

### C. Canvas drags (render-canvas + SongWorkspace)

- Hit testing in `packages/render-canvas`: section block body (drag), right edge (12 px handle,
  11 §6.4), with pointer capture; the renderer draws a lifted block (shadow) following the pointer
  and renders everything else from the **preview document**, so the other blocks part to show the
  drop slot.
- Drag reorder: on each new drop index, `gesture.step(section.move)`; on release, append the
  smart-transition step and `gesture.commit(label)`; `Escape` cancels. Audio follows while playing
  because the engine follows the preview.
- Alt/Option-drag: same, with `section.duplicate` at the drop index (the copy's id fixed at drag
  start so steps fold: the duplicate is created once, then moved).
- Right-edge drag: a ghost with the bar count ("+8 bars" / "−2 bars", snapped to bars); on release
  a popover asks how (Loop / Stretch when longer, Trim when shorter; the AI choices arrive with
  WP-2.7) and commits `section.resize`. No audio preview for resize in this WP.

### D. Verification (Opus)

Vitest (batches, smart transitions, palette, keyboard, menu, gesture → one `section.move`), the
engine tests above, `pnpm verify`, and live on the stack: upload, play, drag Chorus 2 before Verse 2
while playing (audio follows; one commit; undo deep-equal via `__bragi.history`), keyboard-only
path for every action, palette, axe on the open palette and menu (Chromium, Firefox, WebKit).
