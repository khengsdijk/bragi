## Goal

Make the JSON Schemas in `packages/schemas` the single source of truth for every cross-language
contract, and generate from them TypeScript types and Ajv validators, Rust types (typify, into
`bragi-model`) and Pydantic v2 models (into `bragi_common`). WP-0.3 (ops, validate) and WP-0.7
(backend, workers) build directly on the generated types.

**Acceptance (from [12](../../specs/12-roadmap.md)):**
1. The example document in [02 §10](../../specs/02-song-model.md) validates in TS, Rust and Python.
2. JSON → typed → JSON is lossless in all three.
3. (Scope) `pnpm schemas:gen`, plus a check that generated code is up to date, run inside
   `pnpm verify` and mirrored in the dormant `.github/workflows/ci.yml`.

## What shipped

`packages/schemas` holds **63 root types**: the song document and its entities, all 29 v1 ops, 16
analysis result blobs plus the section summary, the two job envelopes and the API error envelope.
One bundle generates four artifacts:

```
packages/schemas/
├─ song/                common, project, source, track, clip, section, arrangement, fx,
│                       automation, region, analysis-ref, asset-meta, op, op-batch, commit, refs
│  └─ ops/              29 files, one per v1 op (02 §4.2)
├─ analysis/            common + ingest-result, rhythm, structure, separation, harmony,
│                       stem-activity, loudness-energy, stem-energy, preview, embedding, tag,
│                       description, section-summary, drum-split, transcribe, lyrics
├─ jobs/                job-request.schema.json, job-event.schema.json
├─ api/                 errors.json (the code registry) + error.schema.json (the envelope)
├─ examples/            63 files, one valid instance per root type
├─ codegen/             bundle.mjs (bundler + convention checks), gen.mjs (the pipeline)
├─ generated/           bundle.schema.json — every schema merged into one 2020-12 document
└─ src/generated/       types.ts · ajv-validators.js · validators.ts
```

| Output | Generated from | Generator |
|---|---|---|
| `packages/schemas/generated/bundle.schema.json` | every source schema | `codegen/bundle.mjs` |
| `packages/schemas/src/generated/types.ts` | the bundle | `json-schema-to-typescript` (dev) |
| `packages/schemas/src/generated/ajv-validators.js` | the bundle | Ajv 2020-12 standalone (runtime, precompiled for the CSP) |
| `packages/schemas/src/generated/validators.ts` | the bundle's root types | `gen.mjs` (a typed façade) |
| `crates/bragi-model/src/generated/mod.rs` | the bundle | `typify` 0.8 via `crates/bragi-schemas-codegen` |
| `services/workers/bragi_common/src/bragi_common/generated/models.py` | the bundle | `datamodel-code-generator` (dev, Pydantic v2) |

Change from the original plan (see "Deviations" below): the Rust driver lives in a workspace crate,
`crates/bragi-schemas-codegen`, not in `packages/schemas/codegen/rust/`, because the pipeline wants
`cargo run -p bragi-schemas-codegen`, cargo already knows the workspace, and the driver then shares
the workspace's pinned dependency versions and lints.

### Conventions, enforced by the bundler

`codegen/bundle.mjs` fails `pnpm schemas:gen` with a list of every violation, so the three
generators keep naming things identically and never silently change a value. The rules (and the
reason for each) are documented in [`packages/schemas/README.md`](../../packages/schemas/README.md);
the ones that cost real effort to discover are:

- **Inline single-value enums are lifted into `$defs`** named `<Owner><Property>`
  (`TrackAddOp` + `op` → `TrackAddOpOp`). typify invents that name on its own; making it explicit is
  the only way `json-schema-to-typescript` and `datamodel-code-generator` agree with it. Without it,
  Python produced 25 classes all named `Op`, `Op1`, … and the real `Op` union was renamed `Op13`.
- **Every object declares `additionalProperties`**: `false` (closed), a subschema (a typed map) or
  `true` (deliberately open). A bare `{ "type": "object" }` is what made `FreeformParams` drop its
  keys in Pydantic — the round-trip test caught it, and the bundler now rejects the shape.
- **Every `$def` must be reachable from a file root**, or `json-schema-to-typescript` (which starts
  at a root) would omit a type that Rust and Python emit.
- **No `format`**: `IsoDate` is a `pattern`, so no language parses a timestamp into a date type that
  re-formats it.

### Pipeline

`pnpm schemas:gen` → `packages/schemas/codegen/gen.mjs`:
1. Bundle every `*.schema.json` under `song|analysis|jobs|api`, checking the conventions above.
2. Fail if `api/errors.json` and the `ErrorCode` enum in `api/error.schema.json` disagree.
3. TypeScript types, precompiled Ajv validators and the typed façade (in memory).
4. Rust: `cargo run -p bragi-schemas-codegen -- <bundle> <out>`, then prepend the generated header
   (which allows the lints generated code cannot satisfy).
5. Python: `datamodel-codegen … --use-type-alias --use-annotated`, then drop its placeholder root
   model and append `ROOT_TYPES`.

`pnpm schemas:check` runs the same pipeline with the Rust and Python generators pointed at a temp
directory and fails, naming each stale file. It runs **first in `pnpm verify`**, and in its own CI
job (it needs pnpm, cargo and uv, so it cannot live in the TypeScript job).

Two generator details worth keeping in `gen.mjs` as comments, because they are invisible and easy to
lose in an upgrade:
- Ajv's standalone output keeps a CommonJS `require()` for its `ucs2length` helper (`minLength`).
  `gen.mjs` rewrites it to an ESM import, because `require` is not defined in an ES module. The
  helper is CommonJS, so the binding is read with `ns.default.default ?? ns.default` — Node binds
  `module.exports`, bundlers honour `__esModule`. The step fails if a `require()` survives.
- `datamodel-code-generator`'s `RootModel` subclasses are unhashable, so a map keyed by a
  constrained ID cannot be validated. `--use-type-alias` emits PEP 695 `type` aliases instead, which
  are hashable and keep the name.

## Test plan (and where each proof lives)

The three test suites read the same files, so they prove the same thing about the same documents.

| Criterion | Proof |
|---|---|
| 02 §10 example validates | `fixtures/projects/example-02-10.json` × Ajv `validateProject` · `bragi-model/tests/schema_contracts.rs` (`the_spec_example_deserializes_into_project`) · `bragi_common/tests/test_schema_contracts.py` (`test_the_spec_example_validates`) |
| The fixture *is* the 02 §10 example | `packages/schemas/src/__tests__/contracts.test.ts`, "is the JSON block in specs/02-song-model.md §10" — it extracts the Markdown block and deep-equals the fixture |
| Lossless round trip | All three suites, for the fixture **and** for every `packages/schemas/examples/*.json`: parse → typed → serialize → parse compared as JSON values (numbers numerically, bool ≠ number, key order ignored), and two serializations byte-identical. Python uses `TypeAdapter` because a union-only root is a type alias, not a model |
| Invalid documents rejected | `fixtures/projects/invalid-cases.json` (15 cases: unknown field at root and nested, bad hash, bad ID prefix, bad enum, missing required, wrong `schemaVersion`, bad timestamp, wrong map type, unknown op discriminator, op with an extra field, float range ×2, non-positive integer bound, empty string), rejected in each language named in its `checkedBy` |
| Every root type covered | Each language asserts its generated `ROOT_TYPES` equals the set of `examples/*.json` basenames, *and* that every example parses into its type |
| Generated code is fresh | `pnpm schemas:check` (in `verify` + CI), plus `packages/schemas/src/__tests__/bundle.test.ts`, which drives the bundler's convention checks one violation at a time |
| Error code registry = envelope enum | `contracts.test.ts`: `api/errors.json` codes equal the generated `ErrorCode` enum (and a `@ts-expect-error` for a code that is not in it) |

## Deviations from the plan as first written

| Planned | Shipped | Why |
|---|---|---|
| `codegen/rust/` driver inside `packages/schemas` | `crates/bragi-schemas-codegen` (workspace member) | `cargo run -p …` from the repo root; shares the workspace's pinned deps and lints |
| `json-schema-to-typescript` on the bundle root | on a synthetic `oneOf` of every root type, which is then stripped | the generator starts at the root, and a `$defs`-only container has no root type |
| `description` siblings on `$ref` kept for every generator | stripped for `json-schema-to-typescript` only | it treats `{ "$ref", "description" }` as a new anonymous type and emitted `AssetHash1`, `AssetHash2`, … |
| `pnpm schemas:check` inside the CI TypeScript job | its own CI job | it regenerates Rust and Python too, so it needs cargo and uv |
| no `analysis/taxonomy.json` | still absent; the `tag` schema keeps labels as strings | its ~500 labels are WP-1.6's job (Q17) |
| Ajv `unicode: false` (to avoid the `ucs2length` require) | rewrote the `require` into an ESM import instead | Ajv 8.20 deprecates `unicode`, and the rewrite keeps Ajv's code-point-correct `minLength` |
| silent assumption that typify checks nothing numeric | integer bounds, patterns and string lengths **are** enforced by typify; only **float** bounds are not | the invalid cases record exactly which language must reject what |
