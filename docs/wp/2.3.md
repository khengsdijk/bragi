# WP-2.3 — FX catalogue, macros & Inspector

- **Spec refs:** [03 §6, §6.1, §11](../../specs/03-audio-engine.md), [07 §4.5](../../specs/07-song-canvas.md), [02 §3.7, §4](../../specs/02-song-model.md) (FxInstance, fx ops, automation targets), [11 §2, §6](../../specs/11-ux-and-accessibility.md), [13](../../specs/13-agent-guide.md)
- **Depends on:** 1.1 (Done)
- **Size:** L
- **Branch:** `wp/2.3-fx`

## Goal

Every `FxType` in `crates/bragi-dsp/fx_catalog.json` sounds, in both hosts, on tracks and the
master; seven plain-language macros ("vibe sliders") drive them; and the Inspector opened from a
ribbon shows solo/mute/volume/pan, the vibe sliders and an expert drawer generated from the
catalogue.

**Acceptance (12):** every FxType has DSP unit tests (impulse/frequency response where
applicable), param smoothing without zipper noise, and catalogue-driven UI. Macros produce
`macroOwned` fx and stay in sync with the Inspector.

## Approach

### 1. DSP framework (`bragi_dsp::fx`) — landed as the first code commit

- `Effect` trait: `kind`, `set_param(index, value)` (target only, clamped, NaN ignored),
  `reset`, `process(left, right, ctx)` in place, `latency`, `tail`. Allocation in `create` only.
- `FxKind` with the catalogue's numeric params as indexed `ParamSpec` tables (names resolved to
  indices at plan-compile time; `match_eq.bands` flattened to `band0..band30`; `sidechain_duck`'s
  `sourceTrack` is routing via `FxContext::sidechain`). `tests/fx_catalog.rs` proves the tables
  equal the JSON.
- `Smoothed`: a critically damped two-pole glide (20 ms default). One pole starts at its steepest
  slope and leaves a kink in a modulated signal; two poles start flat. Filters recompute
  coefficients from smoothed inputs at most every `COEFF_UPDATE_FRAMES` (16) frames.
- `BiquadCoeffs` (RBJ shelf/peak/LP/HP/BP + `magnitude_db`), `Biquad`, `StereoBiquad`.
- `Gain` as the reference effect.
- Shared tests: `tests/common/fx.rs` (`sine_gain_db`, `assert_no_zipper`, `run_stereo`, …),
  `tests/fx_no_alloc.rs` (every kind `create` can build, through every param extreme and block
  size, 0 allocations), `tests/fx_gain.rs`.

### 2. Effects (three parallel batches)

| Batch | Effects | Tests (beyond no-alloc + a zipper test per continuous param) |
|---|---|---|
| A1 filters & image | `eq3`, `filter`, `width`, `transient` | eq3: flat at 0 dB (≤ 0.01 dB), shelf/bell gains at their frequencies vs `magnitude_db`; filter: LP/HP/BP −24 dB/oct slope (an octave past cutoff ≥ 21 dB down), BP peak; width: 0 = mono (S = 0), 1 = bit-exact, 2 = doubled S; transient: attack>0 raises the onset/sustain ratio on a click train, 0/0 is identity |
| A2 dynamics & colour | `compressor`, `saturation`, `limiter`, `lofi`, `chorus` | compressor static curve (−6 dB over threshold at 3:1 → −4 dB of gain reduction ± 0.5), attack/release timing, mix 0 = dry; saturation ×2 oversampled, drive 0 ≈ identity, aliasing of a 5 kHz sine below a bound, odd/even harmonics by tone; limiter: no sample above ceiling (true-peak with ×4 check), 5 ms latency reported, transparent below ceiling; lofi: 16 bit/48 k/0/0 = identity, bits=4 quantises to 16 levels; chorus: mix 0 = dry, modulated delay within depth |
| A3 time & system | `reverb`, `delay`, `sidechain_duck`, `match_eq` | reverb: impulse response decays to −60 dB at `decaySec` ± 25 %, predelay honoured, mix 0 = dry, stereo decorrelated, `tail()`; delay: impulse echo at `timeBeats·60/bpm` s, feedback decay ratio, ping-pong alternates, tempo change follows `ctx.bpm`; sidechain: key at 0 dBFS ducks by `amountDb` ± 1 dB, release timing, no key = identity; match_eq: all bands 0 = identity, a band's gain at its 1/3-octave centre, `amount` scales |

Each batch adds its arms to `create` and its module to `fx/mod.rs` (I resolve the trivial merge
conflicts). Everything stays `wasm32-unknown-unknown`-clean.

**A3 deviation (recorded):** `match_eq` builds each band as a fixed 0 dB-peak RBJ band-pass with
the band gain applied as a smoothed scalar (`y = x + (10^(dB/20) − 1)·BP(x)`) instead of
recomputing RBJ *peaking* coefficients from a smoothed gain. The planned version excites an
audible ring at the band centre when the coefficients change (≈ −41 dBFS during a −18→+18 dB
sweep, which even a slack of 4.0 in the zipper test rejects); the scalar form has the same
centre gain, 0 dB at DC/Nyquist and the same Q, and passes with slack 2.0.

### 3. Engine integration (`bragi-engine`)

- `TrackPlan.fx` / `MasterPlan.fx`: the compiled chain description (kind, params as
  `(index, value)`, bypass, sidechain source track index). The audio thread owns the live
  `Box<dyn Effect>` chains, built off-thread when a plan is installed; a param-only delta
  (`fx.update`, bypass) is sent as messages through the existing command ring, so moving a slider
  never rebuilds a chain or resyncs (07 §9 budget). Structural fx changes (add/remove/reorder)
  rebuild that track's chain off-thread and swap it in.
- Order per track: clips → fx chain → gain/pan/mute/solo (post-fx fader). Sidechain sources are
  processed first (topological order over `sidechain_duck` edges; a cycle bypasses the duck).
- Master: sum → master fx chain → master gain/automation → the existing safety limiter
  (−0.3 dBTP, not removable).
- Automation targets `fx:<fxId>/<param>` (02 §3.8) drive params per block.
- Offline render keeps processing for the max `tail()` after the last clip. Unimplemented kinds
  (none at the end of the WP) bypass.
- Clip-level fx (02 §3.6, "rare") are **out of scope**: a new open question.
- Tests: native + `no_alloc.rs` with fx on every track, conformance (WASM vs native) on a fixture
  with an fx chain, a param-only update does not resync, render tails.

### 4. Macros (`crates/bragi-dsp/macros.json` + TS)

- `macros.json` with the seven v1 macros of 03 §6.1 (`brightness`, `space`, `punch`, `warmth`,
  `vintage`, `intensity`, `distance`), each `{ id, label, range: [-1, 1], drives: [{ fx, param,
  curve: [[x, y]…], mode? }] }`. Labels are the 07 §4.5 vibe-slider pairs.
- `pnpm schemas:gen` copies `fx_catalog.json` and `macros.json` into `@bragi/schemas` as typed
  TS modules (like `taxonomy.json` reaches the worker), so the app and the planner (WP-2.6) read
  one source.
- `macroBatch(doc, scope, macroId, value)` (TS, pure): piecewise-linear curves → creates the
  needed `macroOwned` fx instances (`fx.add` with the drive's params, defaults elsewhere) or
  updates them (`fx.update`); value 0 returns params to defaults (does not remove instances);
  `macroValue(doc, scope, macroId)` inverts the curve from the current params so the slider
  shows the truth after undo or a manual edit in the expert drawer. Tests: round trip, monotonic
  curves, idempotence, undo sync.

### 5. Inspector (`packages/app/src/features/inspector/`)

- Opens when a ribbon is selected (07 §4.5): solo, mute, volume (dB), pan, the six vibe sliders
  of 07 §4.5 (bipolar `Slider` from `@bragi/design`), and an "Expert" drawer that lists the
  track's fx chain with controls generated from the catalogue (sliders with units; `mode` as a
  segmented control; bypass toggles; add/remove/reorder). `macroOwned` fx show "Controlled by
  Space".
- Every change is an op batch through the history store (WP-2.1), so it is undoable; a slider
  drag previews by sending param messages and commits one batch on release.
- Accessible: labelled sliders with value text, keyboard reachable, axe clean; strings in
  `en.json` (11 §2). Master inspector when no ribbon is selected (master fx, gain).

### 6. Verification

`cargo test` (dsp + engine), `pnpm test:conformance`, Vitest (macros, Inspector), and live:
`pnpm dev:backend` + `pnpm dev:web`, upload, select a stem, move "Darker ↔ Brighter" and
"Dry ↔ Spacious" while playing (audible, no clicks — the owner's speakers), undo, reload.
Performance: CPU of a 12-track song with 3 fx per track + master chain in `tests/timing.rs`
(M2 Pro; not the reference machine).

## Deviations (task D)

- **No master volume.** 02 §3.5 stores `arrangement.master.gainDb`, but 02 §4 has no op that
  writes it (`track.update` is the only mixer op). The master inspector therefore shows the
  master fx chain (including `limiter`) and the master-scope vibe sliders, and does not invent a
  volume control. Adding one needs a schema op first (a "Spec gaps" item, not a UI workaround).
- **`intensity` is not a track vibe slider.** 03 §6.1 defines the macro, but 07 §4.5 lists the six
  pairs the Inspector shows (brightness, space, punch, warmth, vintage, distance). The macro
  stays in `MACROS` for the planner and automation; the Inspector iterates `MACROS` and filters to
  the six spec'd ids rather than restating the catalogue.
- **Keyboard changes commit per keystroke; pointer drags commit on release.** Radix reports a
  keyboard step as a commit without a drag, so it is applied as one immediate batch. A pointer
  drag starts `startGesture`, steps on the preview copy and commits once on release (or cancels
  on Escape/pointer cancel).
- **Pan uses the bipolar `VibeSlider`.** It has the centre detent and the left/right pole labels;
  its value text is "20% left" / "Centre" / "20% right". `Slider` stays unipolar (volume, dB
  parameters).
- **One side panel at a time.** The Inspector toggle sits next to the version-history toggle.
  Selecting a single ribbon auto-opens the Inspector; closing it keeps it closed until another
  instrument is selected. With no single track selected the same panel shows the master.
- **No unit-level axe test.** `packages/app` has no axe helper and no axe dependency; the
  Inspector is covered by an e2e axe check in `apps/web/e2e/song-canvas.spec.ts`, which opens a
  track's Inspector and its expert drawer.
- **`mode` labels are UI copy.** The catalogue stores `filter.mode` as `0..2`; the names
  (Low-pass/High-pass/Band-pass) live in `en.json`, because the catalogue carries no labels.

## Outcome

Landed 2026-10-20. Everything was run on an **Apple M2 Pro (macOS)**, not the reference machine.

**Acceptance (12):**

- *Every FxType has DSP unit tests (impulse/frequency response where applicable):* 14 effects,
  16 test files, 129 `bragi-dsp` tests (response, latency, tails, catalogue parity, no allocation
  in `process` for every kind).
- *Param smoothing without zipper noise:* every continuous parameter glides through `Smoothed`;
  `assert_no_zipper` sweeps each effect's parameters (slack ≤ 2.0, including `match_eq`, whose
  design changed for this, see A3 deviation).
- *Catalogue-driven UI:* the expert drawer is generated from `FX_CATALOG` (units, `mode` as a
  segmented control, routing and system params handled), the vibe sliders from `MACROS`.
- *Macros produce `macroOwned` fx and stay in sync with the Inspector:* unit tests for
  `macroBatch`/`macroValue`; live, a "Space" drag on a stem adds the `macroOwned` reverb + width in
  one commit labelled "Space on <stem>", undo returns the slider to "Unchanged", redo restores it,
  and the value survives a reload.

**Engine:** fx chains on tracks and master, carried over across plan swaps (tails survive an
edit), `fx:<id>/<param>` automation, plugin delay compensation (saturation 30 frames, limiter
240), the sidechain source, render tails. 12 tracks × 3 fx + 3 master fx: **0.94 % of real time**
(release, `tests/timing.rs`). WASM vs native conformance: fx fixture nulls at −157 dBFS.

**Live e2e** (`apps/web/e2e/inspector-flow.spec.ts`, real stack): select a stem from the
accessible grid → the Inspector opens → drag "Space": the document does not change during the drag
(the preview copy does), one commit on release → undo/redo → two arrow-key steps on "Brightness"
are two commits → reload keeps the vibe → axe with the expert drawer open. Green in **Chromium,
Firefox and WebKit**. `song-canvas.spec.ts` adds an axe check of the Inspector on the demo page.

**Bug found and fixed while landing it:** the stored-song page (every uploaded song) passed
`selection: none` and dropped selection changes, so nothing could be selected on a real song: the
Inspector never opened from a ribbon and WP-2.1's "Take this part from…" had no region. The
selection now lives in the URL, as on the demo page.

### Follow-up: sidechain source and plugin delay compensation

The former `sidechain_duck.sourceTrack` gap is resolved: `FxInstance` now carries
`sidechainSource?: TrackId`, `fx.update` accepts a tri-state patch (absent / track / `null`), and
`track.remove` clears references to the removed track. See 02 §3.7, §4.2, §4.3 (invariant 8) and
§5.5, and 03 §6. The engine resolves it to `FxSlot::sidechain_source` and feeds
`FxContext::sidechain`; no duck is bypassed merely because it has a source.

Plugin delay compensation is documented in 03 §6.2 and §9: per-track delays bring every chain to
the slowest one, offline renders trim the total output latency, and realtime playback leaves it to
the transport. The fx conformance fixture now also carries `saturation`; its golden WAV was
regenerated and native/WASM still null at −157 dBFS (03 §11).
